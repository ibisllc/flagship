Open source

Flagship est OSS. La valeur de la plateforme appartient à l’utilisateur, sur le matériel de l’utilisateur, avec des clés que l’utilisateur contrôle. La licence garantit que, même si nous disparaissions demain, votre installation continue de fonctionner et que chacun peut forker le code pour le maintenir en vie.

Licence

Flagship est distribué sous la Business Source License 1.1 (BUSL-1.1) avec une Change Date au 2030-05-03. À cette date, tout le code passe automatiquement sous Apache 2.0. D’ici là, vous pouvez :

  • Lire chaque ligne du code source : rien n’est caché.
  • Exécuter toute la pile sur votre propre matériel, pour votre propre usage.
  • Partager des modifications avec des amis qui font tourner leurs propres boîtiers.
  • Forker le projet pour le maintenir en vie si nous disparaissons.

La licence ne restreint qu’une seule chose : monter un concurrent commercial de Flagship en tant que service hébergé avant la Change Date. Cette exception finance le travail qui devrait sinon l’être par du capital-risque, et elle disparaît en 2030.

Dépôt

Le dépôt canonique est github.com/ibisllc/flagship. Il contient tout : le Worker Cloudflare qui fait tourner flagshipserver.com, l’app Fly qui fait tourner flagship.services, le démon du serveur, les créateurs d’apkovl + ISO, les scripts d’installation et les squelettes iOS / Android.

Comment contribuer

  • Rapports de bogues + petites PR : ouvrez une issue ou une PR sur le dépôt canonique. Nous répondons chaque semaine ; les tests doivent passer.
  • Divulgations de sécurité : voir /security et /.well-known/security.txt. Merci de signaler d’abord en privé.
  • Fonctionnalités plus importantes : ouvrez une discussion avant d’écrire du code. Le code repose sur de solides invariants d’architecture (le TLS se termine sur le boîtier de l’utilisateur ; flagship.services ne peut littéralement pas lire le contenu utilisateur ; tout message entre pods est signé en octets canoniques) et nous préférons nous aligner en amont plutôt que rejeter une PR de 2 semaines.

Gouvernance

Le projet Flagship est actuellement maintenu par des contributeurs financés par Anthropic et la communauté ouverte. Il n’existe pas encore de fondation formelle ; nous en créerons une avant la 1.0, quand nous dépasserons le cercle des premiers utilisateurs. D’ici là, « ce qui est fusionné » se décide publiquement sur le gestionnaire d’issues. Il n’y a aucune décision technique à huis clos.

Builds reproductibles

L’ISO de démarrage est reproductible : chacun peut la construire à partir du même tag de source et vérifier que la queue de personnalisation ne fait rien passer à l’insu de l’utilisateur. C’est essentiel pour l’argument de confiance : le support d’installation a trop de poids pour rester invérifiable.

Pourquoi BUSL et pas Apache dès le premier jour ?

Nous avons choisi BUSL-1.1 avec une Change Date en 2030 pour une raison précise : un hyperscaler qui lancerait dès la première année un service hébergé du genre « Flagship, mais c’est notre produit » tuerait la capacité du projet à se financer avant que nous ayons pu livrer ce qui prend du temps (apps mobiles, sauvegarde entre pairs, partenariat matériel). La date de 2030 est le verrou ; ensuite, tout le code est sous Apache 2.0, sans module privé caché. Nous ne faisons pas un coup de bascule à la SSPL.

Contributeurs

La liste complète des contributeurs se trouve dans CONTRIBUTORS.md sur le dépôt canonique. Les contributeurs importants sont ajoutés au site public du projet dès la version suivant l’intégration de leur PR.
