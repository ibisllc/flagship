Vérifier l’image de démarrage

Quand vous gravez un installateur Flagship depuis l’app mobile, elle écrit une image Debian de base que nous dérivons du netinst officiel de Debian, puis ajoute votre recette sous forme d’une petite partition. L’image de base ne contient aucune donnée personnelle et elle est reproductible : vous pouvez la reconstruire à partir de l’ISO publique de Debian et confirmer, octet par octet, qu’elle est exactement Debian d’origine plus une modification publiée et vérifiable. Rien à croire sur parole.

Pourquoi une image de base ? Un téléphone ne peut pas réécrire sur place une ISO de 800 Mo. Nous faisons donc la seule modification structurelle (dire à l’installateur de se configurer automatiquement à partir d’une partition étiquetée) une fois, de façon centralisée et reproductible, et l’app écrit seulement votre recette sur cette partition. Votre recette ne quitte jamais votre appareil ; l’image de base est la même pour tout le monde.

Ce que l’image de base change par rapport à Debian d’origine

  • L’entrée de démarrage par défaut (BIOS et UEFI) lance automatiquement l’installateur avec auto=true priority=critical preseed/file=/cdrom/flagship/preseed.cfg.
  • Un preseed.cfg générique, sans recette, est ajouté dans /flagship/preseed.cfg ; à l’installation, il charge votre recette depuis la partition que l’app ajoute (étiquetée FLAGSHIP).
  • Rien d’autre. Le dispositif de démarrage El Torito / isohybrid est reproduit octet par octet, l’image démarre donc toujours en BIOS et en UEFI.

L’empreinte de l’image de base est épinglée à nouveau avec la base d’origine à chaque version mineure de Debian.

Reproduisez-la vous-même

La dérivation tient en un seul script, iso-seed/build-seed.sh, qui n’utilise que xorriso. À partir de la même base d’origine, il produit exactement l’empreinte ci-dessus avec le xorriso fourni dans Debian 12 ou 13 (les versions plus récentes organisent l’image autrement, exécutez-le donc dans un conteneur Debian), et notre CI la reconstruit avec les deux à chaque modification :

# 1. Download the exact stock base (url + sha are in the app's ISO manifest,
#    and pinned to Debian's official signed SHA256SUMS).
# 2. Re-derive the seed:
git clone https://github.com/ibisllc/flagship
flagship/iso-seed/build-seed.sh debian-13.6.0-amd64-netinst.iso my-seed.iso

# 3. Confirm it matches the published hash:
sha256sum my-seed.iso
# 892cf430928897afa5327a38c107271ed8ced064b5091680509ab6da256295e4

Comment votre recette est appliquée, et pourquoi elle ne peut pas être remplacée

L’image de base est générique : elle ne peut viser aucun boîtier en particulier. Votre recette (un preseed Debian qui contient le blob d’installation signé par votre téléphone) est écrite sur la partition ajoutée. Le système installé fait confiance à la signature de votre téléphone et à rien d’autre ; flagshipserver.com n’est jamais dans cette chaîne de confiance. L’outil de gravure vérifie que le preseed qu’il écrit contient votre signature avant de l’écrire, si bien qu’aucun serveur ne peut lui substituer une autre recette.

La spécification complète

La conception complète (la disposition des partitions, le chargement en chaîne de l’installateur, le modèle de confiance et les garanties de reproductibilité) se trouve dans le dépôt, dans docs/iso-seed-and-on-device-burn.md. Auditez-la, compilez-la, vérifiez-la.
