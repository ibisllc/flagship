快速开始

三个步骤，大约十分钟。

1.安装手机应用，选一个用户名，批准生物识别。你的主密钥绝不会离开手机。

2.在电脑上安装 Flagship Studio。在手机应用中依次选择“添加服务器 → 与 Studio 配对”，并扫描 Studio 显示的二维码。Studio 收到已签名的配方，并为你写入启动 U 盘。插上并启动即可，也可以订购一台开箱即用的成品盒子。

3.在手机上用 vibe coding 做出你的第一个应用。完成。

架构

三个平面。flagshipserver.com 负责身份；flagship.services 是无状态管道（SNI 透传＋隧道中枢）；你的盒子自己用真实的 Let's Encrypt 证书终止 TLS。我们确实无法读取你的数据。

密钥由手机持有。.com 的 Worker 是注册方，从不接触明文内容。.services 的 Fly 应用是一个哑路由器，只能看到加密字节。

Flagship 的工作原理

从头到尾共五个阶段。每一步都由你的手机签名，即使是你第一次注册，我们也看不到你的内容。

1 · 配对你的手机。你安装 Flagship 应用，它会生成一个主密钥，并用存放在手机安全硬件中的密钥将其包裹（iPhone 上是 Secure Enclave，Android 上是硬件支持的 Keystore），通过 Face ID、Touch ID 或指纹解锁。主密钥绝不会离开手机。我们从中再派生出三个密钥：一个用于身份（你的用户名），一个用于备份授权（LUKS 解锁），一个用于工作密钥（每台服务器的秘密）。你选一个用户名，手机对注册请求签名，flagshipserver.com 记录用户名和公钥那一半。没有邮箱、没有密码、没有短信。

2 · 生成并交付配方。你的手机通过 Studio 显示的二维码或短码，直接与 Flagship Studio 配对。确认安全码一致后，手机会生成并发送一份小型已签名配方，其中写明你的服务器名称，并带有短暂、单次有效的过期时间。Studio 获取合适的基础操作系统并写入启动 U 盘：你无需自己挑选或下载系统镜像。

3 · 启动与安装。U 盘在你的硬件上启动一个经过加固的 Linux 基础系统。首次启动脚本在本地验证配方签名，然后从我们的 GitHub 仓库按精确固定的引用获取公开安装程序，只有几百行可审计的 shell。它用 LUKS 格式化磁盘，生成每台盒子独有的身份，申请真实的 Let's Encrypt 证书（DNS-01 通配符），向 flagshipserver.com 注册，然后进入稳态运行。你的手机会亮起：“你的 Flagship 已上线。”

4 · 每次启动都需解锁。盒子重启时，LUKS 加密的根分区不会自动打开。启动阶段会向 flagshipserver.com 轮询是否有已解封的解锁密钥。你的手机被推送唤醒后，要求生物识别，在本地解密密封数据块，并存入有效期 10 分钟的已解封密钥。盒子取用后，该行在读取时即被删除，磁盘随之打开。没有你手机的被盗盒子只是一块砖，连我们也帮不上忙，因为我们从未拥有过已解封的密钥。

5 · 上线。Vibe coding。分享。你在手机上用日常语言描述一个服务，由 LLM 来写（使用你自己的提供商密钥，或 Flagship Inference 的免费额度）。守护进程构建容器，配置限定于该服务的 Postgres 数据库和文件夹，完成部署并注册子域名，一分钟内就能在 app.you.flagship.services 上线。分享只需轻点一下：签名邀请或用户搜索。服务永远看不到 Cookie；守护进程在检查成员资格之后注入身份请求头。

如果你丢了手机。云端恢复只保存你主密钥的加密副本。在 iOS 上，恢复它既需要你的恢复密码短语，也需要访问保存着你 Flagship 通行密钥的 iCloud 钥匙串；Flagship 既无法读取该密钥，也无法重置你的密码短语。没有云端恢复的话，单设备账户必须走更慢的、带等待期的申领流程。

安装与首次启动

安装程序是我们开源仓库中的一个公开 shell 脚本，并通过哈希固定在已签名的配方中。安装程序会用 LUKS 格式化磁盘、生成服务器身份、通过 DNS-01 申请 Let's Encrypt 证书，并向 .com 注册。

此后每次启动，手机都必须批准 LUKS 解锁。没有你手机的被盗盒子只是一块砖。

组装你的服务器

Flagship Studio 能把一台闲置电脑变成你的个人服务器。你只需提供两样东西：你的证书（已签名的配方）和一个 U 盘，它会为你获取合适的加固 Linux 基础系统并把配方烧录进去。下面介绍每个部分是什么以及如何运作。

证书

证书是由你的手机签名的一个小型 JSON 文件。它写明你要创建的服务器，并证明请求来自你：只有手机能授权新的 Flagship 服务器，而手机从不离开你的口袋。

要获得证书，请在电脑上安装 Flagship Studio。Studio 会显示一个二维码和一个短码；在手机应用的“添加服务器”中扫描或输入。确认安全码一致后，应用会为服务器配方签名并直接发送给 Studio。网页应用用户也可以改为下载已签名的 JSON 配方，并在 Studio 中打开。

它是一次性的，且时效很短。证书只在几个小时内有效，并且只授权一台服务器，因此遗留在磁盘上的文件无法被重放。需要时重新生成一个即可。

获取证书

基础操作系统：由我们为你处理

你无需下载或挑选操作系统镜像。构建器会自动获取合适的加固 Linux 基础系统，验证后把你的配方烧录进去。固定使用的基础系统是 Debian 13，选它是因为它能在最广泛的机器上启动。

下面的技术参考适合想确切了解写入内容的人，或在高级“自带镜像”模式下运行构建器的人。其他人可以跳过。

Debian 13 (trixie) amd64 · 推荐

兼容性最好的选择。它的安装程序可以把引导程序放在连最顽固的 UEFI 固件也能找到的位置，因此 Debian 能在其他安装程序放弃的机器上完成安装并启动。它的下载量也更小（网络安装器），同时支持 BIOS 和 UEFI 启动。

启动盘

U 盘只是一次性安装程序，不是服务器本身。它携带你的证书，把一台闲置机器变成你的 Flagship 服务器，然后就完成任务了：你可以将它清空后重复使用。

制作启动盘

把证书和 U 盘拖进构建器并点击“组装”。它会为你获取基础操作系统，并把你的证书烧录到安装镜像内部，这样 U 盘无需从网络获取任何内容，就知道自己要设置哪台服务器。

U 盘会被清空，上面的所有内容都会被覆盖。请使用闲置的 U 盘。

启动目标机器

把 U 盘插到要变成服务器的电脑上并开机，选择 U 盘作为启动设备。安装程序会无人值守运行：划分磁盘分区、安装基础系统、设置 Flagship 守护进程，无需守在键盘前。

无人值守注册

首次启动时，新服务器会生成自己的身份，出示你签名的证书，并注册它的子域名。从这一刻起，TLS 就在你的盒子上终止，flagship.services 成为一个确实无法读取你内容的哑管道。

回收 U 盘

服务器上线后，启动盘就完成了使命。它所携带的证书是一次性的且有时效，所以旧的 U 盘无法被重放。重新格式化后，你可以把它用于任何用途。

手机配对

要使用网页控制台，你需要用手机扫描二维码。手机会显示一个 32 字节的会话令牌，并为 add-paired-session 指令签名，守护进程随后保存该令牌。浏览器把它存为 Cookie，每次管理调用都会携带。

配对记录列在 设置 → 已配对设备 中，随时可以吊销。

应用与清单

应用是你的服务器根据其源码和仓库根目录下的 flagship.app.json 清单构建出的容器。清单写明构建所用的运行时、所需的数据存储（Postgres、文件夹）、允许访问的互联网主机，以及无需登录任何人都能打开的内容。服务器会注入身份请求头，所以应用从不接触密码。

你可以在构建聊天中描述一个应用（AI 编写源码和清单，从不写 Dockerfile），也可以导入一个 git 仓库。无论哪种方式，你的服务器都会构建它、在它自己的沙箱中运行它并为其路由。

清单参考

各字段，在安装应用时都会被检查：

  • schema_version：始终为 1。name：DNS 标签（小写字母、数字和连字符）。version：语义化版本，如 1.2.0。description：可选。
  • runtime：base 为 node-24、python-3.13 或 static，另有 port（应用监听 $PORT）、start（以列表形式给出的启动命令；node-24 默认为 npm start）和 env。以 FLAGSHIP_ 开头的键归服务器所有。自带 Dockerfile 的导入仓库应指定 image，而不是 base。
  • data.stores：postgres: true 为应用提供一个 Postgres 18 数据库（FLAGSHIP_PG_URL，带有 pgvector 和常用扩展）；files: true 提供位于 /data 的可写文件夹（FLAGSHIP_FILES_DIR），重启和重新部署后依然保留。没有 S3 和 Redis。
  • network：subdomain（服务地址为 <subdomain>.<server>.<you>.flagship.services）和 egress（应用请求访问的主机，每个都附带理由）。在你于应用的访问列表中批准之前，不会有任何流量发出。
  • access：enabled: true（应用不能放弃身份验证）、default_role、可选的 custom_roles、public_routes（在仅限成员的应用中任何人都能打开的路径）和 queryable_by。
  • migration.verification：standard（生物识别）或 elevated（生物识别加第二因素），适用于涉及资金、健康或密码数据的应用。
  • 可选：browser.domains，应用可在你服务器自带的浏览器中操作的网站，在安装时批准。
{
  "schema_version": 1,
  "name": "habits",
  "version": "0.1.0",
  "description": "Daily habit tracker.",
  "runtime": { "base": "node-24", "port": 8080, "start": ["node", "server.js"] },
  "data": { "stores": { "postgres": true } },
  "network": { "subdomain": "habits" },
  "access": { "enabled": true, "default_role": "member" },
  "migration": { "verification": "standard" }
}

URL 复用

当你只安装了一个 game 时，URL game.john.flagship.services 直接可用。当你在不同的盒子上装了两个 game 时，这个短 URL 就有歧义，我们会显示一个消歧页面。完整的长格式（game.home.john.flagship.services）始终可用。

恢复

你的账户密钥保存在你的设备上。把它转移到新设备有三种方式，如果这三种你都没有，数据就无法恢复，就像硬件钱包一样。应用在设置过程中会明确说明这一点。

  • 你的另一台设备。在已登录的设备上，打开 设置 → 受信任设备 → 添加设备。在新设备上选择“连接到现有账户”，并扫描“使用配对码加入”下方的二维码，或粘贴其链接（如果你已在别处登录，则用 设置 → 扫描配对码）。两端显示相同的代码，一旦匹配，密钥就会以端到端加密的方式转移过去。
  • 云端备份。如果你开启了恢复，由 iCloud 钥匙串或 Google 密码管理器保存的通行密钥可以解开你密钥的密封副本。在新手机上，用你的账户名登录，并通过 Face ID 或指纹确认。
  • 你的账户密钥文件。设置 → 备份账户密钥 会保存一个受密码短语保护的 .flagshipkey 文件。在新设备上用该密码短语打开它。

在没有可用设备的情况下恢复账户，相当于接管账户，因此需要恢复凭据，并且要等待一段时间，让窃贼无法加快进程：单设备账户等待 3 天，多设备账户等待 24 小时，且还需要你的验证器代码或一个恢复代码。你的其他设备会立即收到通知。只有发起恢复的那台设备可以取消它。之后，每台服务器都会与新设备配对。

API 参考

服务器上的应用可以依赖的内容：

  • 调用者是谁。服务器会丢弃客户端发送的所有 X-Flagship-* 请求头，并设置自己的：X-Flagship-Visitor 为 member、api 或 anonymous；对于成员，X-Flagship-User 是仅在该应用内稳定的 ID（同一个人在两个应用里的 ID 互不关联），X-Flagship-Role 是其级别，即 member、manager 或 master。匿名访客没有用户和角色。
  • 登录。让用户访问应用自己主机上的 /__flagship/sign-in?next=/path（以及 /__flagship/sign-out）。他们在手机上批准，应用从不接触密码。
  • API 密钥。脚本和设备使用 Authorization: Bearer fsk_<keyId>_<secret> 调用应用，该密钥由所有者在应用页面上创建，分为只读或读写。服务器会先校验它，应用会看到 X-Flagship-Visitor: api 和 X-Flagship-Api-Scope。
  • 实时连接。响应以流的方式传输，WebSocket 升级会直接透传。
  • 数据。FLAGSHIP_PG_URL 对应其 Postgres 数据库，FLAGSHIP_FILES_DIR 对应其文件夹。

其余一切，包括你的设备、服务器与 flagshipserver.com 之间的交互，都是签名指令，而不是公共 API。规范位于开源仓库 github.com/ibisllc/flagship，请从 docs/app-apis.md 和 docs/manifest.md 开始看。
