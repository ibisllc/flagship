安全

Flagship 是一款个人云产品。你的手机是信任根，你的数据托管在属于你自己的硬件上。我们对此十分认真。

安全模型

一段话讲清威胁模型

你的手机持有用户主密钥（UMK），由其安全硬件中的密钥包裹（iPhone 上是 Secure Enclave，Android 上是硬件支持的 Keystore）；应用处于解锁状态时，它保存在手机内存中。它绝不会以未包裹的形式离开手机。派生密钥各司其职：BAK 控制服务器启动，IRK 签署账户级操作（如镜像重建和吊销），SWK 被配置到服务器上，让备份无需保持手机唤醒即可自主运行。保存你备份分片的对等主机只能看到不透明的密文。flagshipserver.com 控制平面只是投递渠道和撮合方，它从不接触明文形式的秘密。

两种密钥存储方式。iPhone 和 Android 应用用手机的安全硬件包裹你的密钥（iPhone 上是 Secure Enclave，Android 上是硬件支持的 Keystore，手机具备时还有 StrongBox）：强力的密钥存储。可安装的网页应用把密钥保存在浏览器中，由你的密码短语保护：安全性较弱，你开始使用时我们也会这样告诉你。两者都可以作为同一账户的设备。

我们的承诺

  • 所有对安全至关重要的代码（密钥派生、签名、加密、守护进程、启动路径、移动客户端）均以 BUSL-1.1 公开，并将于 2030-05-03 转为 Apache 2.0。
  • 启动镜像以可复现的方式构建:你可以核实其字节与原版 Debian 一致。
  • 只使用标准原语：Ed25519、X25519、AES-256-GCM、HKDF-SHA-256，以及从 0.3 起与经典算法混合使用的 ML-DSA-65 和 ML-KEM-768。绝无自制密码学。
  • 服务器启动需要手机通过网络签署的批准。被盗的服务器无法自行解锁。
  • 认证域名（flagshipserver.com）与用户内容域名（*.flagship.services）相互分离，因此用户应用无法通过子域名混淆获取会话 Cookie。
  • flagshipserver.com 在物理上无法读取用户内容的 TLS：字节按 SNI 路由，只在你自己的服务器上解密。
  • 绝不做 KYC。我们不收集、存储或公开任何用户的现实身份信息：没有法定姓名、邮箱、电话或政府证件。阅读完整政策 →

0.3 带来的变化

在 0.3 中，我们假定服务器的某些部分可能遭到攻击，并让每个部分只持有其所需的最小权限。简单来说：

  • 服务器程序不再以 root 身份运行。它以普通用户身份运行。少数需要 root 的工作（电源、容器、防火墙、安装版本）都经过一个小型中介程序（broker），它只接受一份固定的类型化请求列表，其他一切都会拒绝并记录。
  • 密钥与服务器程序分开存放。服务器的身份密钥、TLS 密钥和 Let's Encrypt 账户密钥存放在一个独立的密钥服务中。服务器程序请它签名，自己从不持有这些密钥。这是同一台机器上的软件边界，而不是硬件边界。
  • 你的手机在首次接触时固定（pin）每台服务器自己的密钥。新服务器用一个一次性秘密值证明它是由你的配方构建的，并显示一个 6 位代码，你的手机会根据服务器的密钥自行算出这个代码。此后，出示不同密钥的服务器都会被拒绝。
  • 敏感操作需要你的管理员密钥。在已知其管理员的服务器上，更新、级别变更、日志读取、显卡批准等指令，除非由管理员设备签名，否则都会被拒绝。服务器控制接口的每个路由都要经过同一个默认拒绝的检查。
  • 已签名的安装包。服务器从一个由 Flagship 维护者签名的发布包进行安装和更新，该包带有只增不减的序列号和最低运行时版本。安装或更新时，你的服务器上不会运行任何包管理器、编译器或 git 检出。回滚只会切换回磁盘上已有的版本。
  • 启动。每个 VM 预装镜像在首次启动时生成自己的磁盘密钥，并删除共享的出厂密钥。磁盘密钥的密封副本以一个仅用于启动的密钥为接收方；如果服务器有 TPM，打开它的密钥会保存在 TPM 中。我们不对度量启动（measured boot）或证明（attestation）作任何声明。
  • 应用各守其位。每个应用都在 gVisor 下运行，只能访问你批准的互联网主机。应用的数据库迁移在一个严格锁定的一次性容器中运行。从备份恢复的应用启动时，访问列表上没有任何人，直到你批准该列表；它们也只运行备份所记录的那个确切镜像。需要显卡的应用会等待你签名批准。
  • AI 始终被隔离。AI 模型发出的每个工具调用都要经过一个中介程序，它只放行你授予的权限；你的服务器展示给模型的一切内容，都会去除姓名、邮箱地址、时间、语言和网络地址。本地 AI 在服务器上运行，不连接互联网。
  • 恢复会验证你的通行密钥。flagshipserver.com 只有在收到你通行密钥的有效签名后，才会交出云端恢复记录，而新的记录会对其全部内容进行签名。0.3 之前设置的恢复，在你接受应用中一次性的“更新你的账户恢复”提示后，也会获得这项保护。
  • 抗量子基础工作。服务器和手机持有与其 Ed25519 密钥绑定的 ML-DSA-65 密钥，混合通道（X-Wing：ML-KEM-768 加 X25519）也已构建完成，iPhone 和 Android 上有一个可选开启的设置。发布签名、安装包和启动租约只有在我们的签名仪式之后，才需要其中的抗量子部分。以上全部尚待外部审查；这并不表示 Flagship 现在已经抗量子。
  • 问题已修复。0.3 修复了针对整个产品的一次安全审查中阻止发布级别的问题，以及我们自己的对抗性测试套件发现的 24 个问题；该测试套件现在每次发布都会运行。外部评估尚未进行。

没有改变的是：TLS 在你自己的服务器上终止，所以我们读不到你的应用发送的内容。我们的中继能看到连接元数据：哪台服务器、什么时候、多少流量。AI 模型永远不会知道你是谁、你在哪里。

协调披露与赏金

对于限定范围内的严重漏洞，我们会支付赏金，并按公布的 SLA 回应报告。需要协调披露：在修复发布之前，漏洞利用细节须保密。

范围

范围内范围外
  • flagshipserver.com：Cloudflare Worker、所有 /api/* 路由、静态站点，以及域名配置／Cookie 作用域。
  • webapp.flagshipserver.com：网页应用 PWA，包括 WebAuthn／IRK 签名／租约存放／恢复上传等路径。
  • remote.flagshipserver.com：浏览器远程控制界面，包括手机批准流程及其签发的无密钥会话。
  • *.flagship.services：Fly 上的 SNI 透传平面、隧道中枢，以及每台 Flagship 服务器的隧道传输。
  • 由 Flagship Studio 在基于 Debian 的启动镜像上分发的 Flagship 守护进程，包括 ACME、本地 TLS 服务器、数据层（/var/flagship/data/ 下的 Postgres／Forgejo／Chromium，以及各应用的文件卷）。
  • 启动镜像和镜像构建器 Flagship Studio。
  • @flagship/protocol 中的规范字节层：签名/验证例程、密钥派生、加密。
  • Flagship 的 iOS 和 Android 应用。
  • 个人用户所安装应用中的漏洞（这属于应用作者的责任，请直接向其报告）。
  • 自托管的 Flagship 分支（仅官方构建在范围内）。
  • 第三方依赖中的问题：请向上游报告，并抄送给我们。
  • 需要对用户已解锁的手机或笔记本电脑进行物理访问的问题。
  • 针对经过充分审查的原语（Ed25519、X25519、AES-256-GCM、SHA-256、HKDF）的、没有可用 PoC 的理论攻击。
  • 针对公共端点的限流、拒绝服务或流量型攻击。（这方面我们依赖 Cloudflare 的边缘网络。）
  • 在没有 XSS 注入点的静态页面上缺少安全响应头。
  • 由扫描器自动生成、未经人工分析的报告。
  • 针对员工或用户的社会工程学攻击。

响应目标

  • 在2 个工作日内初步确认。
  • 在 7 天内完成分级判定（范围内/外、严重程度）。
  • 按严重程度的修复发布目标：严重级在 7 天内；高危 30 天内；中危 90 天内；低危尽力而为，通常并入下一个版本。
  • 公开披露（署名报告者）：在修复推送到所有自动更新渠道之后，与你协调进行。

赏金发放

状态：预发布阶段，资金尚未完全到位。Flagship 尚未商业发布，赏金计划也尚未获得资金，因此赏金发放将推迟到资金到位之后。下面的档位是资金到位后我们预计支付的金额，并非当前的报价。在此之前，我们会按本政策对报告进行分级、修复和署名，并把每一份合格报告记录为待履行的义务，在商业发布时按这些档位评估。我们宁愿在你投入时间之前告诉你，而不是之后。

在计划获得资金之前，这在实际中意味着：

  • 我们仍按公布的 SLA 进行分级和修复。资金情况不会影响报告的处理速度。下方名人堂中的每份报告都在 SLA 内完成了修复和部署。
  • 每份合格报告都会被记录为待履行的义务，并附上我们评定的严重程度，在商业发布时按下方档位结算。
  • 严重程度由我们自行评估，并会上调。如果你自己的报告比事实所支持的更保守（就像我们收到的第一份报告那样），我们会记录更高的严重程度，而不是你声称的那一档。
  • 署名可以立即提供，形式由你决定，且不附带任何条件。这是我们现在唯一能给你的东西，所以我们更愿意把它做好。
  • 修复发布后不设禁发期。你随时可以公开发布你的发现。如果希望我们做技术准确性审阅，请先联系我们；我们不会要求你淡化任何内容。
  • 如果延迟给你造成了实际困难，请告诉我们。我们宁愿现在听到，也不希望你事后发现我们的资金状况而感到被误导。

安全港

依据本政策善意开展的研究，Flagship 不会采取法律行动。你可以探测生产环境端点，前提是你不得：

  • 访问、修改或删除其他用户的数据，超出证明问题所需的最低限度。请使用你自己的账户。
  • 利用该问题提取测试账户数据之外的内容。
  • 运行会产生持续负载的自动扫描器。
  • 在修复发布之前或双方商定的披露日期之前公布细节（我们的目标最长为 90 天，严重问题可协商）。
