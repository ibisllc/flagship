验证启动种子镜像

当你从移动应用烧录 Flagship 安装程序时，它会写入一个我们从官方 Debian netinst 派生的 Debian 种子镜像，然后把你的配方作为一个小分区附加上去。种子镜像不含任何个人数据，并且可复现：你可以从公开的 Debian ISO 重新构建它，逐字节确认它就是原版 Debian 加上一处公开、可审计的改动。无需轻信我们的话。

为什么要用种子镜像？手机无法就地改写一个 800 MB 的 ISO。所以我们集中、可复现地把唯一一处结构性改动（让安装程序从一个带标签的分区自动配置）只做一次，应用只需把你的配方写到那个分区上。你的配方从不离开你的设备；种子镜像对所有人都一样。

种子镜像相对原版 Debian 的改动

  • 默认启动项（BIOS 和 UEFI）以 auto=true priority=critical preseed/file=/cdrom/flagship/preseed.cfg 自动启动安装程序。
  • 在 /flagship/preseed.cfg 添加一个通用、不含配方的 preseed.cfg；安装时，它从应用附加的分区（标签为 FLAGSHIP）读取你的配方。
  • 除此之外没有任何改动。El Torito / isohybrid 启动结构逐字节原样重现，因此在 BIOS 和 UEFI 上都能照常启动。

固定的哈希值

构件SHA-256
原版基础：Debian 13.6.0 amd64 netinst
Debian 官方签名的 SHA256SUMS		 see debian.org/…/SHA256SUMS
Flagship 种子镜像（由上面的镜像派生） 892cf430928897afa5327a38c107271ed8ced064b5091680509ab6da256295e4

每次 Debian 小版本发布时，种子镜像的哈希值都会与原版基础一起重新固定。

亲自复现

派生过程只是一个脚本 iso-seed/build-seed.sh，只用到 xorriso。基于同一个原版基础，用 Debian 12 或 13 自带的 xorriso 就能得到与上面完全相同的种子哈希（更新的版本会以不同方式排布镜像，所以请在 Debian 容器中运行），我们的 CI 也会在每次改动时用两者重新构建：

# 1. Download the exact stock base (url + sha are in the app's ISO manifest,
#    and pinned to Debian's official signed SHA256SUMS).
# 2. Re-derive the seed:
git clone https://github.com/ibisllc/flagship
flagship/iso-seed/build-seed.sh debian-13.6.0-amd64-netinst.iso my-seed.iso

# 3. Confirm it matches the published hash:
sha256sum my-seed.iso
# 892cf430928897afa5327a38c107271ed8ced064b5091680509ab6da256295e4

你的配方如何生效，以及为什么无法被调包

种子镜像是通用的，因此无法针对任何特定的主机。你的配方（一个带有你手机签名的安装数据的 Debian preseed）被写入附加的分区。安装好的系统只信任你手机的签名，别无其他；flagshipserver.com 从不在这条信任链中。烧录工具在写入之前会确认 preseed 中嵌入的是你的签名，因此任何服务器都无法换成另一份配方。

完整规范

完整设计（分区布局、安装程序的链式加载、信任模型和可复现性保证）位于代码仓库中的 docs/iso-seed-and-on-device-burn.md。审计它，构建它，验证它。
