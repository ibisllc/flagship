验证 Node 运行时

每台 Flagship 服务器的一部分用 TypeScript 编写，运行在 Node.js 上。你的服务器运行的是官方 Node.js 二进制文件，与 Node.js 项目在 nodejs.org 上发布的完全一致：绝不是我们重新构建的副本。下面是每个 Flagship 版本锁定的确切版本和校验和，由 Flagship 的发布密钥签名，你可以据此核对你的服务器，并把两者与 Node 自己签名的列表对照。

这能证明什么，不能证明什么。校验和一致，证明你的服务器运行的正是 Node.js 项目签名、Flagship 批准的那些字节。它不能证明这些字节是由 Node 公开的源代码构建的：那需要可复现构建，是另一项声明。

亲自核对

1. 下载官方归档文件和 Node 签名的校验和列表，并用你从 github.com/nodejs/release-keys（而不是从我们这里）获得的密钥核对 Node 的签名：

curl -fsSLO https://nodejs.org/dist/v24.22.1/node-v24.22.1-linux-x64.tar.gz
curl -fsSLO https://nodejs.org/dist/v24.22.1/SHASUMS256.txt
curl -fsSLO https://nodejs.org/dist/v24.22.1/SHASUMS256.txt.sig
gpg --verify SHASUMS256.txt.sig SHASUMS256.txt
grep ' node-v24.22.1-linux-x64.tar.gz$' SHASUMS256.txt
sha256sum node-v24.22.1-linux-x64.tar.gz

2. 用源代码仓库中固定的发布密钥（密钥绝不来自本网站）核对清单上的 Flagship 签名，并确认其中携带的锁定正是它所签名的那一份：

curl -fsS https://flagshipserver.com/api/runtime/manifest -o runtime-manifest.json
jq -j .lockJson runtime-manifest.json | sha256sum    # equals manifest.lockSha256
git clone https://github.com/ibisllc/flagship && cd flagship && npm ci
npx tsx tools/box-artifact/runtime-manifest.ts verify --manifest ../runtime-manifest.json

3. 在你自己的服务器上（先在 Flagship 应用的服务器页面开启调试访问），计算正在运行的 Node 的哈希值，并与上面可执行文件的 SHA-256 对比：

sha256sum /opt/flagship/.runtime/node/bin/node
/opt/flagship/.runtime/node/bin/node --version

Flagship 应用在每台服务器页面的运行时下显示同样的对比。

服务器如何使用它

  • 运行时锁定（release/runtime-lock.json）是每个已签名版本的一部分。如果某个版本自带的 Node 不是锁定的二进制文件，它会在启用前被拒绝。
  • 服务器获取这份清单，用它已固定的发布密钥核对，拒绝更旧的序号或已过期的清单；如果本网站不可用，就保留上次接受的那份。缺少清单绝不会让一台正常的服务器停下来。
  • 只有当归档文件自身的校验和、Node 的签名列表和 Flagship 的签名清单全部一致时，才会安装新的运行时；否则保留正在运行的那个。

完整设计：更新程序的运行时模块。
