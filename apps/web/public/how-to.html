How to assemble your server.

Flagship Assembler turns a spare computer into your personal server. It needs three things — your certificate, a Linux image, and a USB drive. Here's what each one is and how it works.

Certificate Linux image Boot drive
The Assembler needs

A certificate

The certificate is a small JSON file your phone signs. It names the server you're creating and proves the request came from you — the phone is the only thing that can authorize a new Flagship server, and it never leaves your pocket.

To get one, open flagshipserver.com on your computer and scan the QR code with the Flagship app on your phone. The app signs a certificate for the server and hands it back to the page, which downloads the JSON. Bring that file to the Assembler.

It's single-use and short-lived. A certificate is good for a few hours and authorizes exactly one server, so a leftover file on disk can't be replayed. Generate a fresh one whenever you need it.

The Assembler needs

A Linux image

The Assembler builds your boot drive on top of a stock Linux installer. We test against a small, pinned list — use one of these for a clean, verified install.

Ubuntu Server 22.04.5 LTS amd64 · recommended

The long-term-support server image. Boots on both BIOS and UEFI machines. This is the image the Assembler is tested end-to-end against today.

Why a pinned list? The Assembler verifies the image's SHA-256 against this list before it writes anything. A corrupted download, a tampered mirror, or an untested version is refused — you never have to check a checksum by hand. We add images here only after a real end-to-end install on real hardware.

The Assembler makes

A boot drive

The USB drive is a one-time installer, not the server itself. It carries your certificate, turns a spare machine into your Flagship server, and then it's done — you can wipe and reuse it.

Assemble the drive

Drop your certificate, a recommended Linux image, and a USB drive into the Assembler and hit Assemble. Your certificate is baked inside the installer image, so the drive needs nothing from the network to know which server it's setting up.

The drive is erased — everything on it is overwritten. Use a spare one.

Boot the target machine

Plug the drive into the computer you want to become your server and turn it on, choosing the USB drive as the boot device. The installer runs unattended — partitions the disk, installs the base system, sets up the Flagship daemon. No keyboard babysitting.

Register, unattended

On first boot the new server generates its own identity, presents your signed certificate, and registers its subdomain. From this moment TLS terminates on your box — flagship.services becomes a dumb pipe that literally cannot read your content.

Reclaim the drive

Once the server is live, the boot drive has done its job. The certificate it carried is single-use and time-limited, so an old drive can't be replayed. Reformat the stick and use it for anything you like.
