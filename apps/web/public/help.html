You're stuck. Here's what to try first.

Quick fixes for the four problems we see most often. If none of these unstick you, scroll to the bottom and email a real human.

Quick start

I just want to start.

  1. Install the phone app from /download (or use the web app).
  2. Pick a username; the app will shows a QR scan.
  3. Paste it into the QR on the homepage, write the ISO to a USB stick (8 GB+), boot the target machine from it.

About ten minutes to a real green padlock at you.flagship.services.

Stuck on install

I'm stuck on the install screen.

  1. "No QR scan accepted" — codes expire in 24 hours and are single-use. Shows a new one from the phone.
  2. "No network" — the installer needs DHCP on a wired ethernet port. Wi-Fi is not supported during install. Plug a cable in.
  3. "Disk too small" — minimum is 32 GB. The installer formats whichever disk you point it at; it does not dual-boot.

Still stuck? Capture the screen and email it.

Phone trouble

My phone died.

  1. If you enabled iCloud Keychain or Google Block Store at setup, sign in on the new phone and your identity unwraps with biometrics.
  2. If you didn't, your account is unrecoverable — that's by design (we have no backdoor) and we tried to be clear about it during setup.
  3. The hardware itself is fine. Spinning up a new account against the same box is a clean reinstall.

Full recovery flow: /docs/recovery.

App not loading

An app isn't loading.

  1. Browser shows "DNS error" — your subdomain is propagating. Wait 60 seconds; check /status.
  2. "Cert invalid" / no green padlock — the daemon is renewing. Check the dashboard for "Renewing" pill; usually clears in 90 seconds.
  3. "403 not a member" — the app is identity-gated and your phone hasn't approved your device. Approve from the phone, refresh.

Logs live on your box at journalctl -u flagshipd.

A bit more, by symptom.

Three things that can knock a working install offline. Each one resolves on its own most of the time; if it doesn't, here's where to look.

My install is stuck at "installed"

The install finished and the box powered off so you could unplug the USB stick and power it back on — but after you do, it never comes up. This almost always means the box can't reach the network early in boot, so it can't fetch the key that unlocks its encrypted disk. It's the usual symptom on a Wi-Fi-only box (the disk-unlock step runs before Wi-Fi is available). Two fixes:

  1. Plug in an Ethernet cable. A wired connection is up early enough for the box to fetch its unlock key and finish booting. This is the simplest fix and keeps your disk encrypted.
  2. Or create a new server with disk encryption turned off. In the app's "Create a server" screen (or the web app), uncheck Encrypt disk, then re-burn. A box with the disk unencrypted boots without needing the network to unlock — so it works on Wi-Fi-only setups. The trade-off: your data is no longer encrypted at rest, which is less safe if the box is stolen. Choose this only when a wired connection isn't an option.

The dashboard says "Offline"

The tunnel from your box to flagship.services is down. Check, in order:

  1. Power and network. Is the box on? Is the cable in? Can it reach the internet (ping 1.1.1.1)?
  2. Outbound 443 reachable. Some restrictive networks block long-lived WebSockets. curl https://flagship.services/api/health from the box should return JSON.
  3. Daemon health. SSH in, run systemctl status flagshipd. Restart with systemctl restart flagshipd; recent logs in journalctl -u flagshipd -n 200.

"Cert invalid" in the browser

Your TLS cert lives on the daemon and renews automatically 30 days before expiry. If you're seeing a cert warning:

  1. Wait 90 seconds. Renewals re-issue and reload silently. The dashboard shows a "Renewing" pill while it's happening.
  2. Check the dashboard's cert section. If it says "Failed", the underlying cause is in the daemon log. The most common reason: the box was offline during the renewal window. Triggering a manual renewal from the dashboard fixes it.
  3. Brand-new install with no cert at all: the first issuance happens at boot and takes 30 to 60 seconds. Refresh.

"403 not a member" or "App locked"

Apps default to identity-gated — only the owner and explicitly invited users can hit them. If you're the owner and seeing 403:

  1. Confirm you're signed in on this device. Open the dashboard at https://you.flagship.services/.flagship/; if it asks for pairing, pair.
  2. If you're a guest someone shared the app with: ask them to re-issue the invite. Invite tokens expire after first use.
  3. If the app is supposed to be public, check its manifest's access field. Owner can change it from the dashboard.
