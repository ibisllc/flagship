Die Node-Laufzeit prüfen

Ein Teil jedes Flagship-Servers ist in TypeScript geschrieben und läuft auf Node.js. Dein Server führt das offizielle Node.js-Binary aus, genau so, wie das Node.js-Projekt es auf nodejs.org veröffentlicht: nie eine Kopie, die wir neu gebaut haben. Unten stehen die genaue Version und Prüfsumme, die jede Flagship-Version festlegt, signiert mit den Release-Schlüsseln von Flagship, damit du deinen Server damit vergleichen kannst und beides mit Nodes eigener signierter Liste.

Was das beweist und was nicht. Übereinstimmende Prüfsummen beweisen, dass dein Server dieselben Bytes ausführt, die das Node.js-Projekt signiert und Flagship freigegeben hat. Sie beweisen nicht, dass diese Bytes aus Nodes veröffentlichtem Quellcode gebaut wurden: Dafür braucht es einen reproduzierbaren Build, eine eigene Aussage.

Selbst prüfen

1. Lade das offizielle Archiv und Nodes signierte Prüfsummenliste herunter und prüfe Nodes Signatur mit einem Schlüssel, den du von github.com/nodejs/release-keys hast, nicht von uns:

curl -fsSLO https://nodejs.org/dist/v24.22.1/node-v24.22.1-linux-x64.tar.gz
curl -fsSLO https://nodejs.org/dist/v24.22.1/SHASUMS256.txt
curl -fsSLO https://nodejs.org/dist/v24.22.1/SHASUMS256.txt.sig
gpg --verify SHASUMS256.txt.sig SHASUMS256.txt
grep ' node-v24.22.1-linux-x64.tar.gz$' SHASUMS256.txt
sha256sum node-v24.22.1-linux-x64.tar.gz

2. Prüfe Flagships Signatur auf dem Manifest mit den im Quellcode-Repository hinterlegten Release-Schlüsseln (der Schlüssel kommt nie von dieser Website) und dass der enthaltene Lock der ist, den es signiert:

curl -fsS https://flagshipserver.com/api/runtime/manifest -o runtime-manifest.json
jq -j .lockJson runtime-manifest.json | sha256sum    # equals manifest.lockSha256
git clone https://github.com/ibisllc/flagship && cd flagship && npm ci
npx tsx tools/box-artifact/runtime-manifest.ts verify --manifest ../runtime-manifest.json

3. Berechne auf deinem eigenen Server (mit Debug-Zugriff, eingeschaltet über seine Seite in der Flagship-App) den Hash des laufenden Node und vergleiche ihn mit dem SHA-256 der ausführbaren Datei oben:

sha256sum /opt/flagship/.runtime/node/bin/node
/opt/flagship/.runtime/node/bin/node --version

Die Flagship-App zeigt denselben Vergleich auf der Seite jedes Servers unter Laufzeit.

Wie ein Server es nutzt

  • Der Laufzeit-Lock (release/runtime-lock.json) ist Teil jeder signierten Version. Eine Version, deren mitgeliefertes Node nicht das festgelegte Binary ist, wird abgelehnt, bevor sie eingeschaltet wird.
  • Der Server lädt dieses Manifest, prüft es gegen die Release-Schlüssel, die er schon hinterlegt hat, lehnt eine ältere Sequenz oder ein abgelaufenes Manifest ab und behält das zuletzt akzeptierte, wenn diese Website nicht erreichbar ist. Ein fehlendes Manifest hält nie einen gesunden Server an.
  • Eine neue Laufzeit wird nur installiert, wenn die Prüfsumme des Archivs selbst, Nodes signierte Liste und Flagships signiertes Manifest alle übereinstimmen; sonst bleibt die laufende.

Das vollständige Design: das Laufzeit-Modul des Updaters.
