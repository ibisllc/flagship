Das Boot-Seed prüfen

Wenn du einen Flagship-Installer aus der mobilen App brennst, schreibt sie ein Debian-Seed-Image, das wir aus dem offiziellen Debian-Netinst ableiten, und hängt dann dein Rezept als kleine Partition an. Das Seed enthält keine persönlichen Daten und ist reproduzierbar: Du kannst es aus dem öffentlichen Debian-ISO neu bauen und Byte für Byte bestätigen, dass es genau Standard-Debian plus eine veröffentlichte, überprüfbare Änderung ist. Nichts, was du uns einfach glauben musst.

Warum überhaupt ein Seed? Ein Telefon kann ein 800 MB großes ISO nicht an Ort und Stelle umschreiben. Also machen wir die eine strukturelle Änderung (dem Installer sagen, dass er sich von einer beschrifteten Partition aus selbst konfiguriert) einmal, zentral und reproduzierbar, und die App schreibt nur dein Rezept auf diese Partition. Dein Rezept verlässt nie dein Gerät; das Seed ist für alle gleich.

Was das Seed gegenüber Standard-Debian ändert

  • Der Standard-Booteintrag (BIOS und UEFI) startet den Installer automatisch mit auto=true priority=critical preseed/file=/cdrom/flagship/preseed.cfg.
  • Eine generische preseed.cfg ohne Rezept wird unter /flagship/preseed.cfg hinzugefügt; bei der Installation lädt sie dein Rezept von der Partition, die die App anhängt (Bezeichnung FLAGSHIP).
  • Sonst nichts. Die El Torito-/isohybrid-Bootausstattung wird Byte für Byte übernommen, daher bootet es weiterhin unter BIOS und UEFI.

Selbst nachbauen

Die Ableitung ist ein einziges Skript, iso-seed/build-seed.sh, das nur xorriso verwendet. Aus derselben Standardbasis erzeugt es genau den Seed-Hash oben mit dem xorriso aus Debian 12 oder 13 (neuere Versionen legen das Image anders an, also führe es in einem Debian-Container aus), und unsere CI baut es bei jeder Änderung unter beiden neu:

# 1. Download the exact stock base (url + sha are in the app's ISO manifest,
#    and pinned to Debian's official signed SHA256SUMS).
# 2. Re-derive the seed:
git clone https://github.com/ibisllc/flagship
flagship/iso-seed/build-seed.sh debian-13.6.0-amd64-netinst.iso my-seed.iso

# 3. Confirm it matches the published hash:
sha256sum my-seed.iso
# 892cf430928897afa5327a38c107271ed8ced064b5091680509ab6da256295e4

Wie dein Rezept angewendet wird – und warum es nicht ausgetauscht werden kann

Das Seed ist generisch, es kann also auf keine bestimmte Box zielen. Dein Rezept (ein Debian-Preseed mit dem von deinem Telefon signierten Installations-Blob) wird auf die angehängte Partition geschrieben. Das installierte System vertraut der Signatur deines Telefons und sonst nichts; flagshipserver.com ist nie Teil dieser Vertrauenskette. Der Builder prüft, dass das Preseed, das er schreibt, deine Signatur enthält, bevor er es ablegt, sodass kein Server ein anderes Rezept unterschieben kann.

Die vollständige Spezifikation

Das vollständige Design (Partitionslayout, das Nachladen des Installers, das Vertrauensmodell und die Reproduzierbarkeitsgarantien) liegt im Repository unter docs/iso-seed-and-on-device-burn.md. Prüfe es, bau es, verifiziere es.
