Neu in Flagship 0.3

Versionshinweise. Flagship ist weiterhin kostenlos: In diesem Release gibt es nichts zu kaufen.

Flagship 0.3 ist unser bisher größtes Release. Das meiste davon wirst du nie sehen: Es baut neu, wie dein Server seine Schlüssel aufbewahrt, seine Software installiert und deine Apps ausführt. Manches siehst du jeden Tag: Die Apps sprechen deine Sprache, die Einrichtung eines Servers lässt sich schwerer täuschen, und dein Server kann KI und neue Arten von Apps ausführen, ohne die Cloud von jemand anderem.

Richte einen Server ein, bei dem du sicher sein kannst, dass er dir gehört

  • Dein Telefon prüft, dass es mit deinem neuen Server spricht. Wenn dein Server zum ersten Mal um Genehmigung bittet, speichert dein Telefon den eigenen Schlüssel dieses Servers und prüft ab dann alles daran. Hat die Maschine einen Bildschirm, zeigt sie einen sechsstelligen Code, und dein Telefon zeigt denselben Code über „Genehmigen“. Stimmen sie nicht überein, genehmige nicht. Wenn Flagship Studio den Server auf deinem Computer hostet, prüft Studio den Code für dich.
  • Ein Server, der nicht aus deinem Rezept gebaut wurde, wird abgelehnt. Dein Rezept enthält ein einmaliges Geheimnis, dessen Besitz nur dein eigener Server nachweisen kann.
  • Erstelle den Installations-Stick mit deinem Android-Telefon. Steck einen USB-Stick mit einem OTG-Adapter an dein Telefon, und die App schreibt den Installer selbst, ganz ohne Computer. Der Stick basiert auf einem unveränderten Debian-Image, das jeder neu bauen und Byte für Byte prüfen kann.
  • Server installieren sich aus einem einzigen signierten Paket. Ein neuer Server lädt während der Installation keinen Code mehr aus einem Repository. Er prüft die Signatur eines Pakets der Maintainer von Flagship und installiert es dann ohne weitere Downloads.

Deine eigene Seite und Nachrichten von den Leuten, die sie besuchen

  • Eine öffentliche Seite unter voi.ci/dein-name. Ein Foto, ein Name, eine kurze Beschreibung, deine Links und deine Beiträge. Du erstellst sie im neuen Tab Nachrichten. Jedes Gerät deines Kontos kann Beiträge schreiben; nur ein Administrator-Gerät veröffentlicht sie. Bevor du zum ersten Mal veröffentlichst, erinnert dich die App daran, dass die Seite deinen Benutzernamen mit deinen Apps und Servern teilt, sodass man sie miteinander verbinden kann.
  • Nachrichten. Schalte Nachrichten annehmen ein, und Leute mit einem Flagship-Konto können dir von deiner Seite aus schreiben. Sie melden sich auf voi.ci mit ihrer Flagship-App an. Du siehst jede Person unter einem Namen, der für deine Seite erzeugt wurde, etwa „Besucher 4F3A“, nie unter ihrem Benutzernamen, und du kannst sie umbenennen.
  • Nur du und die absendende Person können sie lesen. Nachrichten sind Ende-zu-Ende-verschlüsselt, mit Post-Quanten-Verschlüsselung, an deine Geräte und die der absendenden Person. Flagship sieht, dass jemand an deine Seite geschrieben hat, wann und wie viel, aber nicht, was.
  • Blockieren und melden. Eine blockierte Person erfährt es nicht, und ihre Nachrichten erreichen dich nicht mehr. Eine Meldung schickt genau diese eine Nachricht an Flagship. Um Spam zu bremsen, ohne nach einer Telefonnummer zu fragen, kann ein neues Konto nur wenige Unterhaltungen am Tag beginnen, und die App lässt sich einmal von Apple oder Google bestätigen, dass sie auf einem echten Gerät läuft. Mehr dazu in den FAQ.

Führe mehr Arten von Apps aus

  • Jede App bekommt ihren eigenen Datenbankserver. Auf neuen Servern läuft die Datenbank einer App für sich, mit eigenen Grenzen für Speicher, Platte und Verbindungen, sodass eine stark ausgelastete App die anderen nicht ausbremsen kann.
  • Apps aus mehreren Teilen. Eine App kann aus bis zu acht Teilen bestehen, etwa einem Webserver und einem Worker, die der Reihe nach starten und als eine App zählen: eine Genehmigung, eine Liste der Websites, die sie erreichen darf, eine Datenbank.
  • WebAssembly-Apps. Eine App kann ein kleines WebAssembly-Programm (WASI) sein. Jede Anfrage läuft in einer frischen Kopie mit harten Grenzen für Zeit und Speicher.
  • Wähle, wie sich jede App aktualisiert. Manuell ist der Standard: Du genehmigst jedes Update. Verzögert hält ein geprüftes Update eine Woche zurück, bevor es installiert wird. Automatisch installiert es sofort. Beide automatischen Varianten übernehmen nur Updates desselben Herausgebers, die keine neuen Berechtigungen verlangen; alles andere wartet auf dich.
  • Apps können darum bitten, mit den Apps einer anderen Person zu sprechen. Wenn eine App auf dem Server von jemand anderem einer deiner Apps Nachrichten senden will, siehst du eine Anfrage und wählst Erlauben, Immer erlauben oder Ablehnen. Ein „Immer erlauben“ kannst du jederzeit zurücknehmen.
  • Apps können einen Webbrowser auf deinem Server nutzen, aber nur auf den Websites, die du bei ihrer Installation genehmigt hast, mit einem eigenen Browser für jede App. Dein Heimnetz und die eigenen Dienste von Flagship bleiben immer außer Reichweite.

Lass KI auf deinem eigenen Server laufen

  • Lokale KI. Öffne „Lokale KI“ auf der Seite deines Servers und lade ein Modell herunter. Deine Apps und deine Builds können es dann nutzen, und es läuft nur auf deinem Server: Deine Prompts und Daten werden nirgendwohin gesendet. Es läuft auf deinem Prozessor oder auf einer Grafikkarte, sobald diese Karte freigegeben wurde. Das Herunterladen des Modells ist das einzige Mal, dass dein Server den Host des Modells kontaktiert.
  • Trainiere ein kleines Modell mit deinen eigenen Daten. Du kannst eines der kleinen Modelle mit den Beispieldaten einer App trainieren, auf deinem Server. Das steht noch am Anfang: nur kleine Modelle.
  • Stimm zu, bevor KI etwas ausgibt. Bevor eine KI-Reparatur deinen eigenen API-Schlüssel oder dein Guthaben bei Flagship Inference nutzt, siehst du eine Schätzung und wer zahlt, und du stimmst zu. Der Betrag, dem du zugestimmt hast, ist eine harte Grenze.
  • KI erfährt weiterhin nie, wer du bist. Aus dem, was dein Server an ein externes KI-Modell sendet, werden jetzt auch Namen, E-Mail-Adressen, Home-Ordner, Zeiten, Zeitzonen, Sprachen und Netzwerkadressen entfernt.

Nutze eine Grafikkarte, mit deiner Erlaubnis

  • Dein Server zeigt seine Grafikkarten auf seiner Seite, jeweils mit der App, die sie belegt.
  • Eine App, die eine Grafikkarte braucht, wartet auf dich. Du bekommst eine Benachrichtigung und genehmigst sie auf deinem Administratorgerät, oder du ziehst die Genehmigung später zurück. Bis dahin läuft die App ohne die Karte, wenn sie kann, oder sagt dir, warum sie es nicht kann.
  • Karten werden vor dem Einsatz freigegeben. Flagship gibt einer App eine Grafikkarte erst, wenn dieses Kartenmodell unsere Hardwaretests bestanden hat. Bis dahin sagen Apps, die eine brauchen, klar, dass sie noch nicht laufen können. Die Software unterstützt Karten von NVIDIA, AMD und Intel.

Behalte die Kontrolle, wenn Flagship nicht erreichbar ist

  • Dein Telefon findet deinen Server in deinem Heimnetz, wenn flagshipserver.com oder unser Relay nicht erreichbar ist. Es sucht deinen Server im selben WLAN und prüft den eigenen Schlüssel des Servers.
  • Grundlegende Kontrolle ohne uns: den Status deines Servers und seine Apps sehen, eine App starten, stoppen oder neu starten, den Server neu starten oder herunterfahren und ein Backup erstellen und auf deinem Telefon speichern.
  • Jede Aktion wird weiterhin von deinem Telefon signiert und von deinem Server geprüft.

Das funktioniert, solange dein Server läuft. Ein Server, der neu startet, braucht weiterhin flagshipserver.com, um seine Platte zu entsperren. Auch das Erstellen eines Kontos, das Hinzufügen eines Geräts und die Wiederherstellung eines Kontos brauchen weiterhin flagshipserver.com.

Lege fest, wie lange dein Server ohne dich läuft

  • Eine Zeitgrenze für jeden Server. Seine Seite zeigt, bis wann er online bleibt, wenn kein Administrator Flagship öffnet, oder „Keine Zeitgrenze“. Ein Administrator wählt 7 Tage, 30 Tage oder keine Zeitgrenze. Keine Zeitgrenze ist die Voreinstellung. Wer Flagship auf einem Administrator-Gerät öffnet, schiebt das Datum nach hinten.
  • Wenn die Zeit abgelaufen ist, stoppen die Apps des Servers, bis ein Administrator Flagship öffnet. Du kannst den Server auch sich selbst sperren lassen: Er startet mit gesperrter Festplatte neu und fährt erst wieder hoch, wenn ein Administrator es auf seinem Telefon genehmigt.
  • Unser Relay setzt das durch, damit ein verlorener oder gestohlener Server deine Apps nicht auf eigene Faust weiter ausliefern kann. Den Server selbst erreichst du weiterhin, um ihn zurückzuholen.

Telefone und Namen

  • Android 10 und neuer. Die Android-App läuft jetzt ab Android 10; vorher brauchte sie Android 13. Google liefert für Android 10, 11 und 12 keine Sicherheitsupdates mehr, deshalb zeigt die App auf diesen Telefonen einen kurzen Hinweis, der ein Update empfiehlt. Alles funktioniert weiterhin. iPhone und iPad brauchen weiterhin iOS 18, Wear OS weiterhin Wear OS 4.
  • Namen haben 3 bis 30 Zeichen. Kontonamen und voi.ci-Linknamen bestehen aus Buchstaben, Ziffern und Bindestrichen, 3 bis 30 Zeichen lang. Der Name einer App in ihrer Webadresse hat höchstens 30 Zeichen. Ein Name, der einem bereits vergebenen zu ähnlich sieht, wird abgelehnt. Ein aufgegebener Name bleibt 30 Tage gesperrt, bevor ihn jemand nehmen kann.

Nutze Flagship in deiner Sprache

Die Apps, die Web-App, diese Website, Flagship Studio und die Seiten, die dein Server Besuchern zeigt, gibt es jetzt auf Englisch, Spanisch, Französisch, Deutsch, brasilianischem Portugiesisch, Japanisch und vereinfachtem Chinesisch. Benachrichtigungen kommen in der Sprache deines Telefons an. Die Übersetzungen sind maschinell erstellte Entwürfe, die Muttersprachler noch nicht geprüft haben. Wenn ein Satz falsch klingt, schreib uns an support@flagshipserver.com.

Eine ruhigere App

  • „Start“, „Aktivität“ und „Einstellungen“ wurden neu gestaltet, auf iPhone, Android und in der Web-App: kürzere Bildschirme, ein einziger Button „Server hinzufügen / wiederherstellen“ und rote Buttons nur für das, was sich nicht rückgängig machen lässt.
  • Genehmige den Start eines Servers von deiner Uhr aus, während dein Telefon gesperrt ist, auf Apple Watch und Wear OS.
  • Das Abmelden fragt zuerst nach Face ID, deinem Fingerabdruck oder der PIN deines Geräts, wann immer es Schlüssel löschen würde.
  • Die Kontowiederherstellung prüft jetzt auch deinen Passkey. Die Apps bitten dich einmal, deine Wiederherstellung zu aktualisieren, damit sie zusätzlich zu deiner Passphrase auch durch deinen Passkey geschützt ist.

Sicherere Updates

  • Ein Server-Update bewährt sich oder tritt zurück. Das neue Release wird neben dem alten installiert und hat drei Starts, um zu beweisen, dass es gesund ist. Schlägt es fehl, kehrt dein Server von selbst zum vorherigen Release zurück. Updates und Rollbacks berühren nie deine Apps, Daten, Schlüssel oder Einstellungen.
  • Updates erreichen zuerst eine kleine Gruppe von Servern und weitere erst, wenn diese gesund sind.
  • Update-Ergebnisse teilen. Ein optionaler Schalter auf der Seite deines Servers, standardmäßig aus, sendet Flagship pro Update eine Quittung, ob es funktioniert hat. Sie nennt keine App und enthält keine Inhalte.
  • Ein neueres Fundament für neue Server. Neue Server führen Apps mit Podman aus und bewahren ihre Schlüssel in kleinen, separaten Programmen auf, die in Rust geschrieben sind. Server, die du schon hast, behalten ihre bisherige Einrichtung.

Für Sicherheitsbewusste

Wir sind davon ausgegangen, dass Teile des Servers angegriffen werden können, und haben jedem Teil nur so viel Macht gegeben, wie er braucht. Die Details stehen auf der Sicherheitsseite.

  • Das Serverprogramm läuft nicht mehr als root. Die wenigen Aufgaben, die root brauchen, laufen über einen kleinen Broker, der eine feste Liste von Anfragen annimmt und alles andere ablehnt.
  • Die Schlüssel liegen getrennt vom Serverprogramm. Die Schlüssel des Servers für Identität, TLS und Let's Encrypt liegen in einem separaten Schlüsseldienst. Das Serverprogramm bittet ihn zu signieren; es hält die Schlüssel nie selbst.
  • Sensible Aktionen brauchen deinen Administratorschlüssel. Updates, Rangänderungen, Journal-Abfragen und Grafikkarten-Genehmigungen werden abgelehnt, sofern dein Administratorgerät sie nicht signiert hat.
  • Befunde aus der Prüfung behoben. Dieses Release wurde über das gesamte Produkt hinweg auf Sicherheit geprüft. Es behebt die veröffentlichungsblockierenden Befunde dieser Prüfung und die 24 Befunde unserer eigenen Angriffs-Testsuite, die jetzt bei jedem Release läuft. Einige Härtungspunkte aus der Prüfung sind teilweise erledigt und werden im nächsten Update fortgesetzt.
  • Grundlagen für Quantensicherheit. Server und Telefone halten ML-DSA-65-Schlüssel neben ihren Ed25519-Schlüsseln, ein hybrider Kanal (ML-KEM-768 mit X25519) wurde entwickelt, und iPhone und Android haben eine Einstellung „Post-Quanten-Schutz“, die du selbst einschaltest. All das wartet noch auf eine externe Prüfung.
  • Prüfe das Node.js, das dein Server ausführt. Ein Teil des Servers läuft auf Node.js, und zwar auf dem offiziellen Build von nodejs.org, nie auf einem, den wir neu gebaut haben. Die Seite jedes Servers hat eine Karte Laufzeit, die vergleicht, was er ausführt, mit dem genauen Build, den sein Release festlegt. Die Laufzeit-Seite zeigt die signierte Liste und wie du es selbst mit den Signaturen von Node prüfst.
  • Was sich nicht geändert hat. TLS endet weiterhin auf deinem eigenen Server, daher können wir nicht lesen, was deine Apps senden. Unser Relay sieht Verbindungsmetadaten: welcher Server, wann und wie viel. Ein KI-Modell erfährt nie, wer oder wo du bist.
