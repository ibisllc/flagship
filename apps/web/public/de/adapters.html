Repo-Adapter

Ein Repo-Adapter ist die Menge an Änderungen, die ein Flagship-Server vornimmt, damit eine Open-Source-App auf Flagship läuft: ein flagship.app.json-Manifest plus alle kleinen Anpassungen, die die App braucht. Das ursprüngliche Repo wird nie verändert.

Geteilt und öffentlich

Wenn die KI eines Flagship-Servers ein öffentliches Open-Source-Repo anpasst, teilt der Server die Anpassung standardmäßig, damit die nächste Person dieses Repo ohne KI installieren kann. Der Eigentümer des Servers kann das Teilen im Import-Bildschirm abschalten. Wir veröffentlichen jede Anpassung unter github.com/ibisllc/flagship-adapters, sodass jeder genau sehen kann, was Flagship-Server anwenden werden, und jeder Server dieselben Dateien erhält.

  • Wir erfassen nie, wer eine gesendet hat. Es wird kein Konto, Server oder keine Adresse angehängt.
  • Wir veröffentlichen sie in täglichen Stapeln, auf den Tag datiert.
  • Wir behalten nur Anpassungen öffentlicher Repos unter einer Open-Source-Lizenz und prüfen sie zuvor.
  • Jede Anpassung steht unter der Lizenz des Repos, das sie anpasst.
  • Lehnen wir eine aus einem behebbaren Grund ab, kann die KI des Servers sie korrigieren und erneut senden.

Wenn eine Anpassung fehlschlägt

Wenn eine Anpassung bei einer Installation nicht baut oder nicht startet, teilt uns der Server mit, welche Anpassung es war und ob sie beim Bauen oder beim Starten scheiterte. Mehr wird nicht gesendet. Der Eigentümer eines Servers kann außerdem auf der Dienstseite mit einer kurzen Notiz ein Problem melden. Notizen bewahren wir privat auf, veröffentlichen sie nie, nutzen sie nur zur Prüfung der Anpassung und löschen sie innerhalb von 90 Tagen, oder 180 Tage nachdem wir die Anpassung zurückgezogen haben, damit wir lernen, was schiefging. Bitte schreib nichts in eine Notiz, das dich identifiziert.

Wenn für eine Anpassung 3 Probleme gemeldet werden, ziehen wir sie zurück, und die KI des nächsten Servers erstellt eine neue.

Die Einzelheiten stehen in unserer Datenschutzerklärung.

Bestimme, wie dein Repo auf Flagship läuft

Committe eine flagship.app.json im Stammverzeichnis deines Repos. Jeder Flagship-Server nutzt sie, statt das Repo selbst anzupassen, und wir behalten oder teilen nie Anpassungen eines Repos, das eine hat – ein Commit nimmt dein Repo also auch aus unserem Index.

Um eine zu erstellen, schreib sie von Hand (siehe Apps & Manifest), oder importiere dein Repo auf deinem eigenen Flagship-Server, prüfe, dass es läuft, nutze dann flagship.app.json holen im Import-Bildschirm und committe die Datei, die du bekommst.

Für Repo-Eigentümer

Wenn du nicht möchtest, dass wir Anpassungen deines Repos behalten, schreib an legal@flagshipserver.com von einer Adresse aus, die zeigt, dass du das Repo kontrollierst, oder eröffne dort ein Issue, das wir überprüfen können. Wir tragen es in do-not-adapt.txt im öffentlichen Index ein, wodurch seine Anpassungen bei der nächsten täglichen Veröffentlichung entfernt werden und Flagship-Server sie nicht mehr verwenden. Die Git-Historie behält frühere Versionen.

Wir können niemanden daran hindern, Open-Source-Code auf dem eigenen Server auszuführen; dort kann dein Repo also weiterhin angepasst werden. Wir behalten oder teilen es nur nicht.
