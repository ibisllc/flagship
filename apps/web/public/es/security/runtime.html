Verifica el entorno de ejecución de Node

Parte de cada servidor Flagship está escrita en TypeScript y se ejecuta en Node.js. Tu servidor ejecuta el binario oficial de Node.js, exactamente como lo publica el proyecto Node.js en nodejs.org: nunca una copia recompilada por nosotros. Abajo están la versión exacta y la suma de verificación que fija cada versión de Flagship, firmadas con las claves de versión de Flagship, para que compruebes tu servidor con ellas y ambas con la lista firmada del propio Node.

Lo que esto demuestra y lo que no. Que las sumas de verificación coincidan demuestra que tu servidor ejecuta los mismos bytes que firmó el proyecto Node.js y que aprobó Flagship. No demuestra que esos bytes se compilaran a partir del código fuente publicado de Node: eso requiere una compilación reproducible, que es otra afirmación distinta.

El manifiesto de entorno de ejecución firmado actual

Cargando el manifiesto firmado…

Todavía no se ha publicado ningún manifiesto de entorno de ejecución. Cada versión sigue incluyendo su propio bloqueo de entorno de ejecución firmado (abajo).

No se pudo cargar el manifiesto. Descárgalo tú mismo: /api/runtime/manifest.

Compruébalo tú mismo

1. Descarga el archivo oficial y la lista de sumas de verificación firmada de Node, y comprueba la firma de Node con una clave que hayas obtenido de github.com/nodejs/release-keys, no de nosotros:

curl -fsSLO https://nodejs.org/dist/v24.22.1/node-v24.22.1-linux-x64.tar.gz
curl -fsSLO https://nodejs.org/dist/v24.22.1/SHASUMS256.txt
curl -fsSLO https://nodejs.org/dist/v24.22.1/SHASUMS256.txt.sig
gpg --verify SHASUMS256.txt.sig SHASUMS256.txt
grep ' node-v24.22.1-linux-x64.tar.gz$' SHASUMS256.txt
sha256sum node-v24.22.1-linux-x64.tar.gz

2. Comprueba la firma de Flagship en el manifiesto con las claves de versión fijadas en el repositorio de código fuente (la clave nunca viene de este sitio), y que el bloqueo que contiene es el que firma:

curl -fsS https://flagshipserver.com/api/runtime/manifest -o runtime-manifest.json
jq -j .lockJson runtime-manifest.json | sha256sum    # equals manifest.lockSha256
git clone https://github.com/ibisllc/flagship && cd flagship && npm ci
npx tsx tools/box-artifact/runtime-manifest.ts verify --manifest ../runtime-manifest.json

3. En tu propio servidor (con el acceso de depuración activado desde su página en la app de Flagship), calcula el hash del Node que se está ejecutando y compáralo con el SHA-256 del ejecutable de arriba:

sha256sum /opt/flagship/.runtime/node/bin/node
/opt/flagship/.runtime/node/bin/node --version

La app de Flagship muestra la misma comparación en la página de cada servidor, en Entorno de ejecución.

Cómo lo usa un servidor

  • El bloqueo de entorno de ejecución (release/runtime-lock.json) forma parte de cada versión firmada. Una versión cuyo Node incluido no es el binario fijado se rechaza antes de activarse.
  • El servidor descarga este manifiesto, lo comprueba con las claves de versión que ya tiene fijadas, rechaza una secuencia anterior o un manifiesto caducado y, si este sitio no responde, conserva el último que aceptó. Que falte el manifiesto nunca detiene un servidor que funciona bien.
  • Un nuevo entorno de ejecución solo se instala cuando coinciden la suma de verificación del propio archivo, la lista firmada de Node y el manifiesto firmado de Flagship; si no, se mantiene el que está en marcha.
