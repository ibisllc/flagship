Verifique o ambiente de execução do Node

Parte de todo servidor Flagship é escrita em TypeScript e roda no Node.js. Seu servidor roda o binário oficial do Node.js, exatamente como o projeto Node.js o publica em nodejs.org: nunca uma cópia recompilada por nós. Abaixo estão a versão exata e o checksum que cada versão do Flagship fixa, assinados pelas chaves de versão do Flagship, para você conferir seu servidor com eles e os dois com a lista assinada do próprio Node.

O que isso prova e o que não prova. Checksums iguais provam que seu servidor roda os mesmos bytes que o projeto Node.js assinou e o Flagship aprovou. Eles não provam que esses bytes foram compilados a partir do código-fonte publicado do Node: isso exige um build reproduzível, que é outra afirmação.

Confira você mesmo

1. Baixe o arquivo oficial e a lista de checksums assinada do Node, e confira a assinatura do Node com uma chave obtida em github.com/nodejs/release-keys, não com a gente:

curl -fsSLO https://nodejs.org/dist/v24.22.1/node-v24.22.1-linux-x64.tar.gz
curl -fsSLO https://nodejs.org/dist/v24.22.1/SHASUMS256.txt
curl -fsSLO https://nodejs.org/dist/v24.22.1/SHASUMS256.txt.sig
gpg --verify SHASUMS256.txt.sig SHASUMS256.txt
grep ' node-v24.22.1-linux-x64.tar.gz$' SHASUMS256.txt
sha256sum node-v24.22.1-linux-x64.tar.gz

2. Confira a assinatura do Flagship no manifesto com as chaves de versão fixadas no repositório do código-fonte (a chave nunca vem deste site), e que o lock que ele traz é o que ele assina:

curl -fsS https://flagshipserver.com/api/runtime/manifest -o runtime-manifest.json
jq -j .lockJson runtime-manifest.json | sha256sum    # equals manifest.lockSha256
git clone https://github.com/ibisllc/flagship && cd flagship && npm ci
npx tsx tools/box-artifact/runtime-manifest.ts verify --manifest ../runtime-manifest.json

3. No seu próprio servidor (com o acesso de depuração ativado na página dele no app Flagship), calcule o hash do Node em execução e compare com o SHA-256 do executável acima:

sha256sum /opt/flagship/.runtime/node/bin/node
/opt/flagship/.runtime/node/bin/node --version

O app Flagship mostra a mesma comparação na página de cada servidor, em Ambiente de execução.

Como um servidor usa isso

  • O lock do ambiente de execução (release/runtime-lock.json) faz parte de toda versão assinada. Uma versão cujo Node incluído não é o binário fixado é recusada antes de ser ativada.
  • O servidor baixa este manifesto, confere com as chaves de versão que já tem fixadas, recusa uma sequência anterior ou um manifesto vencido e mantém o último que aceitou se este site estiver fora do ar. A falta do manifesto nunca para um servidor saudável.
  • Um novo ambiente de execução só é instalado quando o checksum do próprio arquivo, a lista assinada do Node e o manifesto assinado do Flagship concordam; caso contrário, o atual continua.
