セットアップとインストール

古い PC ならどれでも構いません。USB メモリから起動し、スマートフォンとペアリングします。ほとんどの方が約 10 分でオンラインになります。

実際にはどんなハードウェアが必要ですか？

RAM 2 GB 以上、ディスク 32 GB 以上、動作するイーサネットポートを備えた x86_64 マシンならどれでも使えます。古いノートパソコン、NUC、2014 年の Optiplex など、すべて問題ありません。（すでに使っているコンピューターに、Flagship Studio からサーバーを置くこともできます。）OS はビルダーが用意するため、何が動いているかを知る必要はありません。

インストールにはどれくらいかかりますか？

USB メモリを挿してから you.flagship.services で本物のグリーンの鍵マークが出るまで約 10 分です。ほとんどはカーネルの起動と、Let's Encrypt による証明書の発行にかかる時間です。USB メモリを作るには、アプリを Flagship Studio と直接ペアリングします。スマートフォンが署名付きレシピを送り、あとは Studio が行います。

ディスクは消去されますか？

はい。インストーラーは対象ディスクをフォーマットし、あなたのスマートフォンだけが解除できる鍵で LUKS によるディスク全体の暗号化を設定し、堅牢化した Linux ベースを書き込みます。ディスク上にあったものはすべて消えます。インストーラーは 2 回確認し、デバイスのパスを表示します。誰も驚かせないよう最善を尽くしています。

自宅に固定 IP やポート開放は必要ですか？

いいえ。お手元の箱が flagship.services へ外向きの WebSocket を開き、それがトンネルになります。ポート開放も、ダイナミック DNS も、ルーターの設定も不要です。CGNAT でも問題ありません。必要なのは外向きの TCP/443 が通ることだけで、一般向けの回線ならどこでも通ります。

スマートフォンなしでインストールできますか？

実質的にはできませんが、選択肢はあります。強固なセキュリティの経路では、スマートフォンが信頼の起点で、メールとパスワードによる代替手段はありません。スマートフォンを使いたくない場合は、webapp.flagshipserver.com のインストール可能な Web アプリが対等なデバイスとして使えます（Secure Enclave の代わりにパスフレーズと WebAuthn を使用）。鍵の保管は弱くなりますが、完全に自分で管理できるアカウントです。

Studio とのペアリングはどう動きますか？

コンピューターで Flagship Studio を開くと、QR コードと短いコードが表示されます。モバイルアプリで「サーバーを追加」→「Studio とペアリング」を選び、コードをスキャンまたは入力して、両方の画面のセキュリティコードを照合します。スマートフォンがレシピに署名して Studio に直接送ります。ペアリングのセッションは短時間で、一度しか使えません。Web アプリでは、代わりに署名済みレシピをダウンロードできます。

Raspberry Pi で動かせますか？

まだです。現在ビルダーが対象にするのは x86_64 マシンで、ベース OS の ARM ビルドは標準では提供していません。デーモン自体は純粋な TypeScript なので、SSD を付けた Pi 4 でも技術的には動くはずです。手作業で成功した場合は、ぜひ教えてください。

プライバシーとセキュリティ

「私のデータを読めますか？」への構造的な答えは「いいえ」です。バイトが復号された状態でお手元の箱を離れることはありません。実際にどういうことかを説明します。

Flagship は私のデータを読めますか？

データの中身は読めません。ファイル、メッセージ、アプリのデータ、AI プロンプトが、読める形で私たちに届くことはありません。TLS はお手元の箱で終端され、Let's Encrypt 証明書の秘密鍵を持つのはその箱だけなので、flagship.services には暗号化されたバイトが TCP の土管を通り過ぎるのが見えるだけです。私たちが見えるのはメタデータです。アカウントが存在すること、どのサーバーを持ちいつオンラインか、おおよそのトラフィック量、そして下の「Flagship 社は実際に何を保存していますか？」に挙げた項目です。私たちは flagship.services の DNS ゾーンを運用しているため、箱の名前に対する証明書を取得することも技術的には可能です。ただしアプリはお手元の箱自身の署名済み証明書をピン留めしているので、それを拒否しますし、そのような証明書は公開の Certificate Transparency ログに残ります。一方で、通常の Web ブラウザーでは気づけません。誰が何を見られるかの完全な一覧は、メタデータのページにあります。

Flagship 社は実際に何を保存していますか？

ユーザー名とデバイスの公開鍵。各サーバーについては、名前、公開鍵、ハートビートが届く元のアドレス、最終確認時刻、ヘルスレポート、送信された指示（アップデート、バックアップポリシー、移動）。スマートフォン宛てに暗号化された LUKS ロック解除用の封印済み blob。プッシュ通知トークン。デバイスが投稿する監査イベント。アカウントごとのトラフィックと AI 使用量のカウント。さらに、箱が接続した外部 AI ホストの一覧を、アカウントや箱とは紐づけず、合計値のみで 1 つ保持しています。ファイルの内容、プロンプト、チャット、サービスのトラフィックは一切保存しません。完全な一覧は /privacy にあります。

スマートフォンが侵害されたらどうなりますか？

そのアカウントはおしまいです。銀行アプリと同じです。スマートフォンが信頼の起点なので、起点が侵害されれば好きなものに署名されてしまいます。そのため鍵は、スマートフォンのセキュアなハードウェア（iPhone では Secure Enclave、Android ではハードウェア保護された Keystore）が保持する鍵でラップされ、サーバーの起動承認や管理者としての署名といった重要な操作では生体認証を求めます。アプリのロックが解除されている間は一部の鍵がスマートフォンのメモリに載るため、すでにハッキングされてロック解除された状態のスマートフォンは守れません。侵害が疑われる場合は、ペアリング済みの別のデバイスでそのスマートフォンの ID 鍵を取り消してください。

どんな暗号を使っていますか？

標準的なプリミティブのみを使っています。署名は Ed25519、封印された blob には X25519 + AES-256-GCM、鍵導出には HKDF-SHA-256、ディスクには LUKS2/argon2id。通信には、箱自身が取得した本物の Let's Encrypt 証明書を使います。もし独自の暗号を作り始めたら、バグとして報告してください。

ソースコードは公開されていますか？

はい。プロトコル、デーモン、イメージビルダー、クライアントは github.com/ibisllc/flagship で BUSL-1.1 のもとで公開されており、2030 年に Apache 2.0 へ切り替わります。ISO の再現可能ビルドもロードマップに入っており、バイト列がソースと一致することを検証できるようになります。

裁判所の命令で私のデータを提出させられることはありますか？

私たちが持っているものを提出するよう命じられることはあります。私たちが持っているのは、アカウントとサーバーのメタデータ（上記参照）、封印された blob、ルーティング記録です。私たちは通信を終端していないため、トラフィックを復号できません。あなたのサブドメインのルーティング項目を取り消すことは可能で（サービスはオフラインになります）、それは私たちが持つ権限ですが、乱用しないよう努めます。報告すべき要請が出てきた時点で、年次の透明性レポートを公開します。

どんなログを取っていますか？

Cloudflare は flagshipserver.com について、通常のリクエストログ（IP、パス、ステータス）を 30 日間の範囲で保持します。私たちがそれを延長することはありません。flagship.services のリレーは接続ごとのログを書き出さず、カウンターをメモリ上に保持し（合計値は 15 分ごと）、箱の接続が長時間待機状態になったときだけエラー行を表示します。ホスティング基盤の Fly は、独自のポリシーに従って接続メタデータを保持する場合があります。デーモンのログはお手元の箱にローカル保存され、どこにも送信されません。マーケティングサイトやダッシュボードでは、アナリティクス、広告ピクセル、セッションリプレイは使っていません。

サービス

サービスは、お手元の箱で動くコンテナで、ユーザーごとの名前空間で分けられています。

サービスを「バイブコーディング」するとは？

作りたいものを普通の言葉で説明します（「どの観葉植物に水をやったか記録して、5 日以上水切れの植物があれば通知して」など）。LLM がコードを書き、デーモンがビルドし、データ層のスコープ（Postgres のテーブル、オブジェクトストレージ、プッシュ）を選んで、plant-water.you.flagship.services で動かします。所要時間は約 90 秒。気が向けばコードを編集することもできます。

友だちとサービスを共有できますか？

はい、2 通りの方法があります。1 つは、スマートフォンで作成したリンクでアプリの利用に招待する方法で、各自が自分の鍵で参加し、権限レベルはあなたが決めます。もう 1 つは、サーバー全体を別のアカウントと共有し、閲覧または共同管理してもらう方法です（共同管理者がサーバーを破壊することはできません）。中央のデータベースはなく、リストはあなたのサーバー上にあり、変更は管理者デバイスが署名します。

悪意のあるサービスにデータを盗まれないのはなぜですか？

データ層はサービスごと、ユーザーごとに分離されています。各アプリは専用の Postgres データベースと専用のファイルフォルダーを持ち、サンドボックス（gVisor）内で動き、あなたが許可したホストにしかインターネット経由で接続できません。「植物の水やり」サービスがあなたの写真を読むことはできません。ただし、悪意のあるサービスが自分のスコープの中で悪さをすることまでは防げません。インストールする前によく考えてください。

サービスはどの AI プロバイダーを使えますか？

設定したものすべてです。Anthropic、OpenAI、Google、OpenRouter、または OpenAI 互換の任意の API で、ご自身のキーを持ち込めます。キーはデーモン上に、保存時に暗号化された状態で置かれます。既定では、箱は当社のリレーアドレスを経由してプロバイダーに接続します。リレーは暗号化された接続を運び、プロバイダーのホスト名とデータ量は見えますが、プロンプトは見えません。キーごとにこれを無効にできます。キーがない場合、アプリのビルドには当社の内蔵 AI である Flagship Inference が使われ、リクエストは保存されずに第三者のモデルプロバイダーへ中継されます（/privacy を参照）。

サービスをきれいにアンインストールできますか？

はい。アンインストールすると、コンテナ、Postgres データベース、ファイルフォルダー、アクセスリストが削除されます。後でデータに戻りたい場合は、アンインストール前にスナップショットを残しておけます。

Flagship がなくなったら

もっともな質問です。この製品は、そうなっても乗り切れるように設計されています。

御社が事業を終了したら、私のサーバーはどうなりますか？

証明書が切れるまで（証明書の有効期間は約 90 日）は、サーバーもサービスも動き続けます。私たちに依存する機能がいくつかあります。flagship.services 経由のルーティング（トンネルハブは当社のものです）、証明書の更新（チャレンジに当社の DNS ゾーンを使います）、新しいサーバーの作成、新しいデバイスのペアリング、アカウントのリカバリー、そしてルーティングの変更です。コードは公開されているため、誰かが自前のコピーを動かすことはできますが、そのための引き継ぎの仕組みは作っておらず、約束もしていません。

データとアイデンティティはどうなりますか？

データはあなたのディスク上にあり、他のどこにもありませんでした。アイデンティティはスマートフォンの鍵ペアで、私たちが存続しているかどうかに依存しません。flagshipserver.com のユーザー名は会社がなくなれば消えますが、その土台となる公開鍵はあなたのものです。アカウントキーとサーバーのバックアップ（今すぐバックアップ）を保管しておけば、別の場所で再構築できます。

ソースコードは御社より長く残りますか？

はい。BUSL-1.1 の変更日は 2030-05-03 です。たとえ会社が明日なくなっても、ライセンスによりコードベース全体が 2030 年に Apache 2.0 になり、GitHub のミラーも変わらず公開され続けます。

見つかりませんでしたか？

support@flagshipserver.com までメールしてください。実際の人間がすべて読んでいます。インストールがうまくいかない場合はまず /help を、セキュリティに関する質問は、このページより詳しい /security をご覧ください。
