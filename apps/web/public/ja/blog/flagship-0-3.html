Flagship 0.3 の新機能

リリースノート。Flagship は引き続き無料で、このリリースに購入できるものはありません。

Flagship 0.3 は、これまでで最大のリリースです。その大部分は目に見えません。サーバーが鍵を保管し、ソフトウェアをインストールし、アプリを動かす仕組みを作り直しました。一方で、毎日目にする変化もあります。アプリがあなたの言語で表示され、サーバーのセットアップがだまされにくくなり、ほかの誰かのクラウドを使わずに、サーバーで AI や新しい種類のアプリを動かせるようになりました。

確実に自分のものだとわかるサーバーをセットアップ

  • スマートフォンが、新しいサーバーと通信していることを確認します。 サーバーが初めて承認を求めたとき、スマートフォンはそのサーバー自身の鍵を保存し、以後はすべてをその鍵と照合します。マシンに画面がある場合は 6 桁のコードが表示され、スマートフォンの「承認」の上にも同じコードが表示されます。一致しない場合は承認しないでください。Flagship Studio がお使いのコンピューター上でサーバーをホストする場合は、Studio がコードを確認します。
  • あなたのレシピから作られていないサーバーは拒否されます。 レシピには一度しか使えないシークレットが含まれており、それを持っていることを証明できるのはあなた自身のサーバーだけです。
  • Android スマートフォンでインストーラー用の USB メモリを作成。 OTG アダプターで USB メモリをスマートフォンに接続すると、アプリが自らインストーラーを書き込みます。コンピューターは不要です。USB メモリは、誰でも再ビルドしてバイト単位で確認できる公式の Debian イメージから作られます。
  • サーバーは署名付きの 1 つのパッケージからインストールされます。 新しいサーバーは、インストール中にリポジトリからコードをダウンロードしなくなりました。Flagship のメンテナーによる 1 つのパッケージの署名を確認し、それ以上のダウンロードなしでインストールします。

もっと多くの種類のアプリを動かす

  • アプリごとに専用のデータベースサーバー。 新しいサーバーでは、各アプリのデータベースが独立して動作し、メモリ、ディスク、接続数の上限もそれぞれに設けられるため、1 つのアプリが忙しくてもほかのアプリが遅くなることはありません。
  • 複数のパーツで構成されるアプリ。 1 つのアプリを、Web サーバーとワーカーのように最大 8 つのパーツで構成できます。パーツは順番に起動し、1 つのアプリとして扱われます。承認は 1 回、接続できるサイトのリストも 1 つ、データベースも 1 つです。
  • WebAssembly アプリ。 アプリを小さな WebAssembly（WASI）プログラムにすることもできます。リクエストごとに新しいコピーで実行され、時間とメモリに厳しい上限があります。
  • アプリごとにアップデート方法を選べます。 既定は手動で、すべてのアップデートをあなたが承認します。段階的では、確認済みのアップデートをインストール前に 1 週間保留します。自動では、すぐにインストールします。段階的と自動のどちらも、同じ公開元からの、新しい権限を求めないアップデートだけを受け入れます。それ以外はあなたの判断を待ちます。
  • アプリが他の人のアプリとのやり取りを求めることができます。 他の人のサーバー上のアプリが、あなたのアプリにメッセージを送りたい場合は、リクエストが表示され、「許可」「常に許可」「拒否」から選べます。「常に許可」はいつでも取り消せます。
  • アプリはサーバー上の Web ブラウザーを使えます。 ただし、インストール時にあなたが承認したサイトに限られ、ブラウザーはアプリごとに分かれています。自宅のネットワークと Flagship 自身のサービスには、常にアクセスできません。

自分のサーバーで AI を動かす

  • ローカルAI。 サーバーのページから「ローカルAI」を開き、モデルをダウンロードします。以後はアプリやビルドがそのモデルを使え、モデルはあなたのサーバー上でのみ動作します。プロンプトやデータがどこかに送られることはありません。モデルはプロセッサーで動作し、グラフィックカードが認定された後はそのカードでも動作します。サーバーがモデルの配布元に接続するのは、モデルをダウンロードするときだけです。
  • 自分のデータで小さなモデルをトレーニング。 アプリのサンプルデータを使って、小さなモデルの 1 つをサーバー上でトレーニングできます。まだ初期段階のため、小さなモデルに限られます。
  • AI が費用を使う前に同意を。 AI による修復でご自身の API キーや Flagship Inference のクレジットを使う前に、見積もりと誰が支払うかが表示され、あなたが同意します。同意した金額は超えることのない上限になります。
  • AI があなたが誰かを知ることは、引き続きありません。 サーバーが外部の AI モデルに送る内容からは、名前、メールアドレス、ホームフォルダー、時刻、タイムゾーン、言語、ネットワークアドレスも取り除かれるようになりました。

あなたの許可のもとでグラフィックカードを使う

  • サーバーのページに、そのサーバーのグラフィックカードの一覧が、各カードを使っているアプリとともに表示されます。
  • グラフィックカードが必要なアプリは、あなたを待ちます。 通知が届くので、管理者デバイスから承認します。承認は後から取り消すこともできます。それまでは、アプリはカードなしで動作できる場合はそのまま動作し、できない場合はその理由をお知らせします。
  • カードは使用前に認定されます。 Flagship は、その型番のカードが当社のハードウェアテストに合格した後でなければ、グラフィックカードをアプリに割り当てません。それまでは、カードが必要なアプリは、まだ動作できないことをはっきりとお知らせします。ソフトウェアは NVIDIA、AMD、Intel のカードに対応しています。

Flagship に接続できないときも管理を続けられます

  • flagshipserver.com や当社のリレーに接続できないときは、スマートフォンが自宅のネットワーク上でサーバーを見つけます。同じ Wi-Fi 上でサーバーを探し、サーバー自身の鍵を確認します。
  • 私たちがいなくてもできる基本操作：サーバーの状態とアプリの確認、アプリの起動・停止・再起動、サーバーの再起動・シャットダウン、バックアップの作成とスマートフォンへの保存。
  • すべての操作は引き続きスマートフォンが署名し、サーバーが確認します。

これはサーバーが動作している間だけ機能します。再起動したサーバーのディスクのロック解除には、引き続き flagshipserver.com が必要です。アカウントの作成、デバイスの追加、アカウントのリカバリーにも、引き続き flagshipserver.com が必要です。

Flagship をあなたの言語で

アプリ、Web アプリ、このウェブサイト、Flagship Studio、そしてサーバーが訪問者に表示するページが、英語、スペイン語、フランス語、ドイツ語、ブラジルポルトガル語、日本語、簡体字中国語で利用できるようになりました。通知はスマートフォンの言語で届きます。翻訳は機械による下書きで、ネイティブスピーカーによるレビューはまだ行われていません。おかしな文があれば、support@flagshipserver.com までお知らせください。

より落ち着いたアプリ

  • ホーム、アクティビティ、設定を再設計しました（iPhone、Android、Web アプリ）。画面は短くなり、「サーバーを追加 / 復元」ボタンは 1 つにまとまり、赤いボタンは元に戻せない操作だけに使います。
  • スマートフォンがロックされたままでも、ウォッチからサーバーの起動を承認できます（Apple Watch と Wear OS）。
  • 鍵を消去することになる場合は、サインアウトの前に Face ID、指紋、またはデバイスの PIN を求めます。
  • アカウントのリカバリーでもパスキーを確認するようになりました。 パスフレーズに加えてパスキーでも保護されるよう、アプリから一度だけリカバリーの更新を求められます。

より安全なアップデート

  • サーバーのアップデートは、正常であることを自ら証明するか、元に戻ります。 新しいリリースは古いリリースと並べてインストールされ、正常であることを証明するために 3 回の起動の機会が与えられます。失敗した場合、サーバーは以前に動いていたリリースに自動的に戻ります。アップデートとロールバックが、アプリ、データ、鍵、設定に触れることはありません。
  • アップデートはまず少数のサーバーに届き、それらが正常であることを確認してから、さらに多くのサーバーに届きます。
  • アップデート結果を共有。 サーバーのページにある任意のスイッチ（既定はオフ）をオンにすると、アップデートごとに、成功したかどうかを示す受領記録が 1 件 Flagship に送られます。アプリを特定する情報もコンテンツも含みません。
  • 新しいサーバー向けの新しい基盤。 新しいサーバーは Podman でアプリを動かし、Rust で書かれた小さな独立したプログラムに鍵を保管します。すでにお持ちのサーバーは現在の構成のままです。

セキュリティを重視する方へ

サーバーの一部が攻撃されうることを前提に、各部分が持つ権限を必要最小限にしました。詳しくはセキュリティのページをご覧ください。

  • サーバープログラムは root で動作しなくなりました。 root が必要な数少ない処理は小さなブローカーを経由します。ブローカーは決められたリストの要求だけを受け付け、それ以外はすべて拒否します。
  • 鍵はサーバープログラムとは別の場所にあります。 サーバーの ID 鍵、TLS 鍵、Let's Encrypt 鍵は、独立した鍵サービスに置かれます。サーバープログラムは鍵サービスに署名を依頼するだけで、鍵を持つことはありません。
  • 重要な操作には管理者の鍵が必要です。 アップデート、権限レベルの変更、ジャーナルの読み取り、グラフィックカードの承認は、管理者デバイスが署名していない限り拒否されます。
  • レビューでの指摘事項を修正。 このリリースでは、製品全体のセキュリティレビューで出荷停止レベルとされた指摘事項と、当社の敵対的テストスイートによる 24 件の指摘事項を修正しました。このテストスイートは現在、すべてのリリースで実行されています。
  • 耐量子化の土台。 サーバーとスマートフォンは Ed25519 鍵に加えて ML-DSA-65 鍵を持ち、ハイブリッドなチャネル（ML-KEM-768 と X25519）も実装済みです。また iPhone と Android には、任意で有効にできる「耐量子保護」の設定があります。これらはすべて外部レビュー待ちです。
  • 変わっていないこと。 TLS は引き続きあなた自身のサーバーで終端されるため、私たちはアプリが送る内容を読めません。当社のリレーに見えるのは接続のメタデータ、つまりどのサーバーか、いつか、どれだけの量かです。AI モデルが、あなたが誰でどこにいるかを知ることはありません。
