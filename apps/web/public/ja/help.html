Flagship
ホームよくある質問ドキュメントステータス

行き詰まったときに、まず試すことです。

最もよくある 4 つの問題への簡単な対処法です。どれでも解決しない場合は、一番下までスクロールして、人間にメールしてください。

クイックスタート

とにかく始めたい。

  1. /download からスマートフォンアプリをインストールします（Web アプリでも可）。
  2. コンピューターに Flagship Studio をインストールします。
  3. アプリでサーバーを作成し、Studio の QR コードまたは短いコードでペアリングしたら、Studio でインストール用 USB メモリ（8 GB 以上）を書き込みます。

you.flagship.services で本物のグリーンの鍵マークが出るまで約 10 分です。

インストールで止まった

インストール画面で止まっています。

  1. 「ペアリングコードが受け付けられません」：Studio を開き直して新しい QR コードと短いコードを表示し、もう一度試してください。
  2. 「ネットワークがありません」：インストーラーには有線イーサネットポートでの DHCP が必要です。インストール中は Wi-Fi に対応していません。ケーブルを挿してください。
  3. 「ディスク容量が不足しています」：最小は 32 GB です。インストーラーは指定したディスクをフォーマットします。デュアルブートにはしません。

まだ解決しませんか？ 画面を撮影して、メールで送ってください。

スマートフォンのトラブル

スマートフォンが壊れました。

  1. セットアップ時に iCloud キーチェーンまたは Google Block Store を有効にしていれば、新しいスマートフォンでサインインすると、生体認証であなたのアイデンティティが展開されます。
  2. 有効にしていなければ、アカウントは復元できません。これは設計上のことで（私たちにバックドアはありません）、セットアップ時にもできるだけ明確にお伝えしています。
  3. ハードウェア自体は問題ありません。同じ箱で新しいアカウントを作るのは、クリーンインストールにあたります。

復旧手順の全体は /docs/recovery をご覧ください。

サービスが読み込めない

サービスが読み込まれません。

  1. ブラウザーに「DNS エラー」と表示される：サブドメインが伝播中です。60 秒待ってから、/status を確認してください。
  2. 「証明書が無効」／グリーンの鍵マークが出ない：デーモンが更新中です。ダッシュボードの「更新中」表示を確認してください。通常は 90 秒ほどで解消します。
  3. 「403 メンバーではありません」：サービスは ID で保護されていて、あなたのデバイスがスマートフォンで承認されていません。スマートフォンから承認してから、再読み込みしてください。

ログはお手元の箱の journalctl -u flagshipd にあります。

症状別にもう少し詳しく。

正常に動いていた環境をオフラインにしてしまう 3 つの原因です。たいていは自然に解消しますが、解消しない場合の確認箇所を示します。

インストールが「インストール済み」のまま進まない

インストールは完了し、USB メモリを抜いて電源を入れ直せるよう箱の電源が切れましたが、その後いつまでも起動しません。これはほぼ必ず、起動の早い段階で箱がネットワークに届かず、暗号化ディスクを解除する鍵を取得できないことを意味します。Wi-Fi のみの箱でよく起きる症状です（ディスクのロック解除は Wi-Fi が使える前に実行されるため）。対処は 2 つあります。

  1. イーサネットケーブルを挿します。 有線接続は十分早く立ち上がるので、箱が解除鍵を取得して起動を完了できます。最も簡単な方法で、ディスクも暗号化されたままです。
  2. または、ディスク暗号化をオフにして新しいサーバーを作成します。 アプリ（または Web アプリ）の「サーバーを作成」画面で ディスクを暗号化 のチェックを外し、書き込み直してください。ディスクが暗号化されていない箱は、ロック解除にネットワークを必要とせず起動するため、Wi-Fi のみの環境でも動作します。代償として、保存時のデータが暗号化されなくなり、箱が盗まれた場合の安全性は下がります。有線接続がどうしても使えない場合にだけ選んでください。

ダッシュボードに「オフライン」と表示される

箱から flagship.services へのトンネルが切れています。次の順に確認してください。

  1. 電源とネットワーク。箱の電源は入っていますか？ ケーブルは挿さっていますか？ インターネットに届きますか（ping 1.1.1.1）？
  2. 外向きの 443 に届くか。制限の厳しいネットワークでは、長時間続く WebSocket が遮断されることがあります。箱から curl https://flagship.services/api/health を実行して JSON が返れば正常です。
  3. デーモンの状態。SSH でログインして systemctl status flagshipd を実行します。再起動は systemctl restart flagshipd、直近のログは journalctl -u flagshipd -n 200 で確認できます。

ブラウザーで「証明書が無効」と表示される

TLS 証明書はデーモン上にあり、有効期限の 30 日前に自動で更新されます。証明書の警告が表示される場合は次を確認してください。

  1. 90 秒待ちます。 更新は再発行と再読み込みが静かに行われます。その間、ダッシュボードには「更新中」と表示されます。
  2. ダッシュボードの証明書セクションを確認します。 「失敗」と表示されている場合、原因はデーモンのログにあります。最も多い原因は、更新期間中に箱がオフラインだったことです。ダッシュボードから手動で更新を実行すれば解決します。
  3. 新規インストールで証明書がまったくない場合：初回の発行は起動時に行われ、30〜60 秒かかります。再読み込みしてください。

「403 メンバーではありません」または「サービスがロックされています」

サービスは既定で ID によって保護されており、所有者と明示的に招待されたユーザーだけがアクセスできます。所有者なのに 403 が表示される場合は次を確認してください。

  1. このデバイスでサインインしているか確認してください。https://you.flagship.services/.flagship/ でダッシュボードを開き、ペアリングを求められたらペアリングします。
  2. サービスを共有された招待ユーザーの場合は、招待を再発行してもらってください。招待トークンは最初の使用後に失効します。
  3. サービスを公開にするつもりなら、マニフェストの access フィールドを確認してください。所有者はダッシュボードから変更できます。

人間と話したい。

すべてのメールを実際の人間が読んでいます。support@flagshipserver.com に、試したこと、見た内容、ダッシュボードの URL またはデバイスパスを添えてメールしてください。通常 1 日以内に返信します。「blocked（進行不能）」と書いていただければ、より早く対応します。
