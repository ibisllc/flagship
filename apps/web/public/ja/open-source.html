オープンソース

Flagship は OSS です。プラットフォームの価値は、ユーザーのハードウェア上で、ユーザーが管理する鍵のもとで、ユーザーのものになります。たとえ明日私たちがいなくなっても、あなたのインストールは動き続け、誰でもコードベースをフォークして存続させられることを、ライセンスが保証します。

ライセンス

Flagship は Business Source License 1.1（BUSL-1.1）でライセンスされており、変更日は 2030-05-03 です。その日にコードベース全体が自動的に Apache 2.0 へ再ライセンスされます。それまでの間は、次のことができます。

  • ソースコードのすべての行を読む。隠しているものはありません。
  • スタック全体を、自分のハードウェアで、自分の用途のために動かす。
  • 自分の箱を動かしている友人と、改変を共有する。
  • 私たちがいなくなったとき、プロジェクトをフォークして存続させる。

ライセンスが制限するのは 1 つだけです。変更日より前に、商用のホスト型 Flagship-as-a-Service の競合サービスを立ち上げることです。この例外は、本来ならベンチャーキャピタルに頼らざるを得ない開発を支えるもので、2030 年に消滅します。

リポジトリ

正規のリポジトリは github.com/ibisllc/flagship です。flagshipserver.com を支える Cloudflare Worker、flagship.services を支える Fly アプリ、サーバーデーモン、apkovl／ISO ビルダー、インストールスクリプト、iOS／Android の雛形など、すべてが入っています。

貢献の方法

  • バグ報告と小さな PR： 正規リポジトリに Issue または PR を作成してください。返信は週単位で行い、テストは通過している必要があります。
  • セキュリティの開示： /security と /.well-known/security.txt をご覧ください。まずは非公開で報告してください。
  • 大きな機能： コードを書く前にディスカッションを開いてください。このコードベースには強いアーキテクチャ上の不変条件があり（TLS はユーザーの箱で終端される、flagship.services はユーザーコンテンツを文字どおり読めない、ポッド間のメッセージはすべて正規バイト列で署名される）、2 週間かけた PR を却下するより、事前にすり合わせたいと考えています。

ガバナンス

Flagship プロジェクトは現在、Anthropic の資金提供を受けたコントリビューターとオープンなコミュニティによって維持されています。正式な財団はまだありませんが、1.0 に到達し、初期ユーザーを超えて成長する前に設立する予定です。それまでは、「何をマージするか」は Issue トラッカー上で公開の場で決められ、非公開の技術的決定は一切ありません。

再現可能なビルド

起動用 ISO は再現可能です。同じソースタグから誰でもビルドでき、個人化のためのトレーラーがユーザーの目を盗んで何かを紛れ込ませていないことを検証できます。これは信頼の訴求に欠かせません。インストールメディアは影響が大きすぎて、検証不能のままにしておけません。

なぜ最初から Apache ではなく BUSL なのか？

変更日を 2030 年とする BUSL-1.1 を選んだのは、特定の理由からです。初年度にハイパースケーラーが「Flagship そっくりだが自社製品」というホスト型サービスを運営すれば、時間のかかるもの（モバイルアプリ、ピアバックアップ、ハードウェア提携）を提供できる前に、プロジェクトが自力で資金を得る力を失ってしまいます。2030 年という日付が関門で、それ以降はコードベース全体が、隠れた非公開モジュールなしで Apache 2.0 になります。SSPL のような後出しの条件変更ではありません。

コントリビューター
