Node ランタイムを検証する

Flagship のサーバーの一部は TypeScript で書かれ、Node.js 上で動いています。あなたのサーバーが動かしているのは、Node.js プロジェクトが nodejs.org で公開しているとおりの公式 Node.js バイナリです。私たちが再ビルドしたコピーではありません。以下に、Flagship の各リリースが固定する正確なバージョンとチェックサムを、Flagship のリリース鍵による署名付きで示します。これを使ってサーバーを確認し、さらに両方を Node 自身の署名付きリストと照合できます。

これで証明できること、できないこと。チェックサムが一致すれば、サーバーが Node.js プロジェクトの署名し Flagship が承認したものと同じバイト列を動かしていることが証明されます。そのバイト列が Node の公開ソースからビルドされたことまでは証明しません。それには再現可能なビルドという別の主張が必要です。

自分で確認する

1. 公式アーカイブと Node の署名付きチェックサム一覧をダウンロードし、私たちからではなく github.com/nodejs/release-keys から入手した鍵で Node の署名を確認します。

curl -fsSLO https://nodejs.org/dist/v24.22.1/node-v24.22.1-linux-x64.tar.gz
curl -fsSLO https://nodejs.org/dist/v24.22.1/SHASUMS256.txt
curl -fsSLO https://nodejs.org/dist/v24.22.1/SHASUMS256.txt.sig
gpg --verify SHASUMS256.txt.sig SHASUMS256.txt
grep ' node-v24.22.1-linux-x64.tar.gz$' SHASUMS256.txt
sha256sum node-v24.22.1-linux-x64.tar.gz

2. ソースリポジトリに固定されているリリース鍵（鍵がこのサイトから来ることはありません）でマニフェストの Flagship の署名を確認し、含まれているロックが署名対象のものであることを確かめます。

curl -fsS https://flagshipserver.com/api/runtime/manifest -o runtime-manifest.json
jq -j .lockJson runtime-manifest.json | sha256sum    # equals manifest.lockSha256
git clone https://github.com/ibisllc/flagship && cd flagship && npm ci
npx tsx tools/box-artifact/runtime-manifest.ts verify --manifest ../runtime-manifest.json

3. 自分のサーバーで（Flagship アプリのサーバーのページからデバッグアクセスを有効にして）、動いている Node のハッシュを計算し、上の実行ファイルの SHA-256 と比べます。

sha256sum /opt/flagship/.runtime/node/bin/node
/opt/flagship/.runtime/node/bin/node --version

Flagship アプリでも、各サーバーのページのランタイムに同じ比較が表示されます。

サーバーでの使われ方

  • ランタイムロック（release/runtime-lock.json）は署名付きリリースの一部です。同梱の Node が固定されたバイナリでないリリースは、有効化される前に拒否されます。
  • サーバーはこのマニフェストを取得し、すでに固定しているリリース鍵で確認します。古いシーケンスや期限切れのマニフェストは拒否し、このサイトが停止しているときは最後に受け入れたものを使い続けます。マニフェストがなくても、正常なサーバーが止まることはありません。
  • 新しいランタイムがインストールされるのは、アーカイブ自体のチェックサム、Node の署名付きリスト、Flagship の署名付きマニフェストがすべて一致したときだけです。一致しなければ、今動いているものがそのまま使われます。

詳しい設計：アップデーターのランタイムモジュール。
