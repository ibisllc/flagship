ブートシードを検証する

モバイルアプリから Flagship のインストーラーを書き込むと、アプリは公式の Debian netinst から私たちが派生させた Debian のシードイメージを書き込み、そこにあなたのレシピを小さなパーティションとして追加します。シードには個人データが含まれず、再現可能です。公開されている Debian の ISO から作り直し、それが標準の Debian に公開済みで監査可能な変更を加えただけのものであることを、1 バイト単位で確認できます。私たちの言葉を信じる必要はありません。

なぜシードが必要なのか。スマートフォンでは 800 MB の ISO をその場で書き換えられません。そこで、唯一の構造的な変更（ラベル付きのパーティションから自動設定するようインストーラーに指示すること）を、中央で再現可能な形で一度だけ行い、アプリはそのパーティションにレシピを書き込むだけにしています。レシピがデバイスの外に出ることはなく、シードは全員共通です。

シードが標準の Debian から変えている点

  • 既定のブートエントリー（BIOS と UEFI）は、auto=true priority=critical preseed/file=/cdrom/flagship/preseed.cfg でインストーラーを自動起動します。
  • レシピを含まない汎用の preseed.cfg が /flagship/preseed.cfg に追加されます。インストール時には、アプリが追加したパーティション（ラベル FLAGSHIP）からレシピを読み込みます。
  • それ以外は何も変えていません。El Torito / isohybrid のブート構成は 1 バイト単位でそのまま再現されるため、BIOS でも UEFI でも起動します。

シードのハッシュは、Debian のポイントリリースごとに標準ベースと一緒に固定し直されます。

自分で再現する

派生処理は xorriso だけを使う 1 本のスクリプト iso-seed/build-seed.sh です。同じ標準ベースからであれば、Debian 12 または 13 に含まれる xorriso で上と完全に同じシードのハッシュが得られます（新しいリリースではイメージの配置が異なるため、Debian のコンテナー内で実行してください）。私たちの CI も変更のたびに両方で作り直しています。

# 1. Download the exact stock base (url + sha are in the app's ISO manifest,
#    and pinned to Debian's official signed SHA256SUMS).
# 2. Re-derive the seed:
git clone https://github.com/ibisllc/flagship
flagship/iso-seed/build-seed.sh debian-13.6.0-amd64-netinst.iso my-seed.iso

# 3. Confirm it matches the published hash:
sha256sum my-seed.iso
# 892cf430928897afa5327a38c107271ed8ced064b5091680509ab6da256295e4

レシピの適用方法と、すり替えられない理由

シードは汎用なので、特定のボックスを狙うことはできません。あなたのレシピ（スマートフォンが署名したインストール用データを含む Debian の preseed）は、追加されたパーティションに書き込まれます。インストールされたシステムが信頼するのはスマートフォンの署名だけで、flagshipserver.com がその信頼の経路に入ることはありません。書き込むツールは、preseed にあなたの署名が含まれていることを確認してから書き込むので、どのサーバーも別のレシピにすり替えることはできません。

仕様の全文

パーティション構成、インストーラーのチェーンロード、信頼モデル、再現性の保証を含む設計の全体は、リポジトリの docs/iso-seed-and-on-device-burn.md にあります。監査し、ビルドし、検証してください。
