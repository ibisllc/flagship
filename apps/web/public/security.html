Security at Flagship

Flagship is a personal-cloud product. Your phone is the trust root, and you're hosting your own data on hardware you own. We take that seriously.

Threat model in one paragraph

Your phone holds your User Master Key (UMK) inside the Secure Enclave / StrongBox. It never leaves the phone unwrapped. Derived keys do specific jobs: BAK gates server boot, IRK signs account-level operations like image-rebuild and revocation, and SWK is provisioned to the server so backup runs autonomously without keeping your phone awake. Peer hosts who store your backup shards only ever see opaque ciphertext. The flagshipserver.com control plane is a delivery channel and matchmaker; it never sees secrets in the clear.

What we promise

  • All security-critical code (key derivation, signing, encryption, server daemon, boot path, mobile clients) is open source under Apache 2.0.
  • The boot image is built reproducibly. You can verify the bytes match the source.
  • Cryptographic primitives are standard: Ed25519 signatures, AES-256-GCM encryption, HKDF-SHA-256 for derivation. No homemade crypto.
  • Server boot requires a phone-signed approval over the network. A stolen server cannot self-unlock.
  • The auth domain (flagshipserver.com) is separate from the user-content domain (*.flagship.services) so user apps cannot reach session cookies via subdomain confusion.

Scope

In scopeOut of scope
  • Protocol crate (key derivation, signing, encryption)
  • Server daemon
  • Boot image and image-builder
  • iOS and Android apps
  • Control-plane API on flagshipserver.com
  • Tunnel transport from each Flagship server
  • Domain configuration / cookie scoping
  • User-deployed apps (security is the user's responsibility)
  • Denial-of-service against our infrastructure
  • Automated scanner output without proof of impact
  • Issues in third-party dependencies — please report upstream and copy us
  • Social engineering of staff or users

How to report a vulnerability

Two channels:

  1. Email: security@flagshipserver.com. Encrypted reports are encouraged — PGP key fingerprint will be published here once minted.
  2. Web form: /security/report.html for low-friction submissions.

Response targets

  • Acknowledge receipt within 48 hours.
  • Initial triage and severity assessment within 5 business days.
  • Critical issues fixed within 7 days; high within 30; medium within 90.

Disclosure policy

  • Coordinated disclosure. Please give us a reasonable window (we aim for 90 days, negotiable for critical issues).
  • Don't exfiltrate user data or disrupt service while testing. Use your own account.
  • We do not currently operate a paid bug bounty. We will publicly credit reporters in our hall of fame, and as the project matures we'll revisit monetary rewards.
