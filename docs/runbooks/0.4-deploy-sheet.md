# 0.4 deploy sheet: what you need ready, in order

`bash scripts/release.sh --list` shows the 48 steps (0.4 added step 11, "Sign the webapp shell"); `--phase A`
then `--phase B` run them, `--only N` runs one. `docs/runbooks/final-deploy.md` is the long form. This sheet is
what is new in 0.4 and the order to do it in. Everything a web console does (App Store Connect, Play Console,
Stripe, Oblivious Network, Cloudflare, Let's Encrypt) is in `docs/runbooks/0.4-browser-tasks.md`, written for a
Claude-in-browser session: start it first, because Apple's agreements, Play's payments profile, Stripe's answer
and Let's Encrypt's rate-limit increase take days.

Nothing in this sheet has been run. It was written on 2026-11-17 from `RELEASE-0.4-JOURNAL.md`.

## 0. Before anything (days ahead)

1. **Browser tasks with a lead time** (`0.4-browser-tasks.md`): Apple Paid Apps agreement, banking, tax and the
   Small Business Program; the Play payments profile; Stripe's yes on prepaid vouchers
   (`payments-setup.md` §0.1) and the accountant's tax answer (§0.2); the Let's Encrypt rate-limit request for
   `fshp.app` (F17); Oblivious Network's paid plan; the APNs key check for VoIP pushes.
2. **The P items of 0.3 that are still open** (journal "P"): P1 the update-required notice for 0.2 apps (on
   `main` today it is `release.sh --only 45`; after 0.4 lands on `main` it is step 46); P1b the runtime manifest
   re-sign before **~2026-12-20** (step 10; the release run re-signs it anyway); P6 the demo server.
3. **Every 0.4 branch merged into `release/0.4`**: the UI pass (`0.4/ui-pass`), CI (`0.4/ci`: F11, F6 and F15)
   and this release prep (`0.4/release-prep`). Then on `release/0.4`: `npx tsc -b`, `npm run i18n`,
   `npm run parity`, `node scripts/check-versions.mjs`, `npx vitest run` (full), `RELEASE=1 bash
   scripts/release-guard.sh`, `npm run release-manifest` (green except the known hardware receipts).
4. **The gym gate on the final commit.** R1 (every group, both stacks) and the R2 payments/proxy groups are green
   on earlier `release/0.4` commits. Step 14 runs the gym again on the pinned commit; one green run per group is
   enough, and failures caused by Let's Encrypt are logged, not rerun.
5. **Hold `playstore-test-0725`** untouched while any store review is open.

## 1. Land `release/0.4` on `main` (fast-forward)

Only `main` deploys. `main` has two commits `release/0.4` does not have as ancestors:
`881f7757e` (Terms: the legal minimum, already on `release/0.4` as `86739fc31`, with the section renumbered) and
`eb43ae84c` (gym relays off between runs, carried onto `release/0.4` by `0.4/release-prep` as a cherry-pick).
So a plain fast-forward fails. Pick one (owner):

- **Linear (owner's rule since 2026-10-24):** rebase `release/0.4` onto `origin/main` in a scratch worktree, skip
  the two replays whose content is already there (`git rebase --skip` on the cherry-pick and on any commit that
  only re-does the terms text), run the checks of section 0 item 3 again, push `release/0.4` with `--force-with-lease`,
  tell every open worktree. Then:
- or **one merge commit:** on `release/0.4`, `git merge -s ours origin/main -m "Take main's terms and gym-relay
  commits (already here)"` after checking `git diff origin/main release/0.4 -- apps/web/public/terms.html
  scripts/gym-relays.sh` shows only 0.4's own changes.

```sh
git fetch origin
git log --oneline origin/release/0.4..origin/main          # must print nothing now
git checkout main && git merge --ff-only origin/release/0.4 && git push origin main
```

Then start the run on `main`: `bash scripts/release.sh --new --phase A` (it pins `origin/main`).

### DNS cleanup (with step 22, by hand in Cloudflare)

1. **`fshp.app`**: delete the old mirror's proxied `*` and `www` records (AAAA `100::`); keep the proxied `@` (the

   Do it right after the step 23 deploy (the new `.com` has no `*.fshp.app` route).

## Rollback

`.com`: `npx wrangler rollback` in `apps/com` (additive tables stay). Relay: `fly.mesh.toml` (TS hub, mesh kept),
then `fly.toml` + `flyctl scale count 2` (mesh off), as `final-deploy.md` 8f. Box release: a box whose update fails
its health gate rolls back; stop the canary at 0% (step 34). Stores: halt the phased release in App Store Connect,
halt the rollout in the Play Console. A payment rail: delete its secret (the rail reads off at once).
