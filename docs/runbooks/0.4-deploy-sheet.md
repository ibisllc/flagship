# 0.4 deploy sheet: what you need ready, in order

`bash scripts/release.sh --list` shows the 32 steps (fitted to 0.4 on 2026-11-21: every listed step is one this
release runs, the one-time setup of 0.3 is a read-only check, step 10 signs the webapp shell); `--phase A` then
`--phase B` run them, `--only N` runs one. `docs/runbooks/final-deploy.md` is the long form. This sheet is
what is new in 0.4 and the order to do it in. Everything a web console does (App Store Connect, Play Console,
Stripe, Oblivious Network, Cloudflare, Let's Encrypt) is in `docs/runbooks/0.4-browser-tasks.md`, written for a
Claude-in-browser session: start it first, because Apple's agreements, Play's payments profile, Stripe's answer
and Let's Encrypt's rate-limit increase take days.

Written on 2026-11-17 from `RELEASE-0.4-JOURNAL.md`; step numbers follow the fitted `release.sh` (2026-11-21).

## 1. Land `release/0.4` on `main` (fast-forward)

Only `main` deploys. `main` has two commits `release/0.4` does not have as ancestors:
`881f7757e` (Terms: the legal minimum, already on `release/0.4` as `86739fc31`, with the section renumbered) and

```sh
git fetch origin
git log --oneline origin/release/0.4..origin/main          # must print nothing now
```

**Fail-safe (owner rule: our infrastructure failing never breaks the rest).** A calls failure must never break
messages or pages, and this is what keeps it so:

- Every call route answers 404 without the `VOICI_CALL_ROOM` binding (`voiciCallsEnabled`); messages, pages and the
  front door don't read it.
- On voi.ci a failed or refused call shows one sentence on the call sheet ("They aren't taking calls right now." …);
  the page and Send me a message stay as they were. The ring watch survives failed fetches (`da0cc4c7f`).
- A VoIP or call push that fails is that call's missed call; message pushes go through their own sender.
- **No off switch for calls alone.** In an outage or an abuse wave, the voi.ci brake (`VOICI_ENABLED` anything but
  `"on"`, commit to `main`, `.com` deploy) stops pages, messages and calls together and leaves voi.ci a shortener.

After the `.com` deploy, the live checks (one green run is enough): a browser on voi.ci calls an owner's iPhone with
the app closed and locked, and an Android phone; the owner calls a visitor back from the app; a call to a page with
calls off answers the sentence; a message and a page view still work during a call; `npm run ops -- workers --hours
24` shows no new errors on the call routes.
