# 0.4 final round: the YubiKey steps on the Chromebook (and the browser brief)

Written 2026-11-23 for one session: the owner is away from the Mac (reached remotely) with a Chromebook and both
YubiKeys. The Mac does everything that needs no YubiKey (store builds, the catalog, the `.com` deploys, the gym); the
Chromebook does the three YubiKey steps of `scripts/release.sh` and the web consoles (Claude in Chrome). Nothing
here needs the Mac's release state: `release.sh` runs each step from its own state on the Chromebook.

| Where | What | Needs |
|---|---|---|
| Mac | iOS 1.3 (11) archive + upload, Android 14 AABs, `.com` deploy (website, webapp v254) | nothing from the owner (Xcode may ask for a sign-in) |
| Chromebook, terminal | release.sh **6** endorse the box release, **7** sign and publish the box artifacts, **10** sign the webapp shell v254 | YubiKey (PIN + touch, about 6 times) |
| Mac | release.sh **8** the release catalog (opens the box release's first canary stage), `.com` redeploy, gym groups for the box changes, canary widening (days) | the catalog keys' drive mounted on the Mac |
| Chromebook, Chrome | TestFlight 1.3 (11), App Store 1.3 submission, Play 14 upload + submission | the owner's yes at every [OWNER CONFIRMS] |

Order: the Mac's store uploads and the Chromebook's steps 6, 7, 10 can run at the same time. Step 8 waits for 7.
The second `.com` deploy waits for 7 and 10. Browser part B waits for the Play bundles to reach the Chromebook.

## 1. Set up Linux on the Chromebook (once, about 20 minutes)

1. ChromeOS Settings → About ChromeOS → Developers → **Linux development environment**: turn on (or open it). Its
   disk needs **at least 40 GB** (same page → Disk size): the repo, two `npm ci` and the box artifacts.
2. Plug in a YubiKey. Settings → Developers → Linux → **Manage USB devices** → turn on the **Yubico YubiKey**. Do this
   again after every re-plug or Linux restart (ChromeOS does not keep it).
3. In the Linux terminal (Debian 12):

```sh
uname -m                                   # x86_64 or aarch64: decides the age-plugin-yubikey line below
sudo apt update
sudo apt install -y git curl jq build-essential python3 pcscd pcsc-tools libpcsclite-dev age gnupg dnsutils
sudo systemctl enable --now pcscd
pcsc_scan                                  # must list "Yubico YubiKey"; Ctrl-C to stop

# Node 22+ (Debian's is too old)
curl -fsSL https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc && nvm install 24 && node --version

# GitHub CLI
sudo mkdir -p -m 755 /etc/apt/keyrings
curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg >/dev/null
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list >/dev/null
sudo apt update && sudo apt install -y gh

# age-plugin-yubikey 0.5 (opens the PQ release key)
#   x86_64:  the release binary
mkdir -p /tmp/apy && curl -fsSL -o /tmp/apy.tgz https://github.com/str4d/age-plugin-yubikey/releases/download/v0.5.0/age-plugin-yubikey-v0.5.0-x86_64-linux.tar.gz \
  && tar -xzf /tmp/apy.tgz -C /tmp/apy && sudo install "$(find /tmp/apy -type f -name age-plugin-yubikey)" /usr/local/bin/
#   aarch64 (or if the download fails): build it
#   curl https://sh.rustup.rs -sSf | sh -s -- -y && source ~/.cargo/env && cargo install age-plugin-yubikey
age-plugin-yubikey --version
```

4. Logins (each opens the Chrome browser; finish there):

```sh
gh auth login                              # GitHub.com, HTTPS, browser; the account that can push to ibisllc/flagship
```

5. The code and the maintainers tool:

```sh
git clone https://github.com/ibisllc/flagship.git ~/flagship
cd ~/flagship && npm ci
npx wrangler login                         # Cloudflare (the account that owns flagship-com); uploads the box artifacts
npx wrangler whoami
git clone https://github.com/ibisllc/maintainers.git ~/flagship/maintainers
cd ~/flagship/maintainers && npm ci && npm run build && npm install --no-save pcsclite@1.0.1
```

6. The two release-key files from the Mac (the owner receives them as `release-key-files.tgz`; neither is a
   secret on its own: the key is encrypted to the two YubiKeys, the other file only names their slots):

```sh
mkdir -p ~/.flagship-release && chmod 700 ~/.flagship-release
tar -xzf ~/Downloads/release-key-files.tgz -C ~/.flagship-release     # pq-release-key.age, yubikey-identities.txt
chmod 600 ~/.flagship-release/*
```

   (ChromeOS: move the file from the Files app's Downloads into "Linux files" first, or use
   `/mnt/chromeos/MyFiles/Downloads/release-key-files.tgz` after sharing the Downloads folder with Linux.)

7. Check the YubiKey works for both kinds of signature before any real step:

```sh
cd ~/flagship
echo test | node scripts/yubikey-sign.mjs     # PIN + touch; prints "<pubkey> <signature>"; the pubkey starts 2137e739f00550b0 (the ca-track key; if not, plug in the other YubiKey)
age-plugin-yubikey --list                      # shows the flagship-release slot of the plugged-in key
```

If `yubikey-sign` says the card is busy or not found: `gpgconf --kill scdaemon` (GnuPG holds the card), check
`pcsc_scan`, and re-share the YubiKey in ChromeOS Settings (step 2).

## 2. The three YubiKey steps (about 45 minutes, most of it waiting for GitHub Actions)

Before starting: `git -C ~/flagship pull && git -C ~/flagship log -1 --oneline origin/main` must show the commit
the Mac session named (it said "main is ready" with that sha), and nobody else may push to main meanwhile.

Run each from `~/flagship`, in this order. Each previews first and asks before anything outward; the PIN and touch
are the owner's (a Claude session on the Chromebook runs the command and waits; it never types the PIN).

```sh
bash scripts/release.sh --only 6     # endorse the release commit: preview, typed yes, PIN + touch; pushes the endorsement to main
bash scripts/release.sh --only 7     # box artifacts: dispatches box-artifact.yml (~20 min), signs amd64 + arm64 manifests
                                     #   (PIN + touch each), uploads to R2, gVisor mirror, commits the box release, pushes
bash scripts/release.sh --only 10    # sign webapp shell v254: PIN + touch for Ed25519, then PIN + touch to open the PQ key
```

Gates (the script checks each; say which one failed if it stops):
- 6: `node scripts/latest-endorsed-release.mjs` prints the commit just endorsed.
- 7: both manifests verify; `curl -fsSI https://flagshipserver.com/build/iso/flagship-box-<pin12>-amd64.manifest.json`
  answers 200; the "Install box release" commit is on origin/main.
- 10: `release/webapp-shell/v254.json` is on origin/main.

Release.sh's other steps are NOT for the Chromebook. Step 5 (CA lease) is not needed: the lease runs to 2027-01-17.
Step 9 (runtime manifest) is not needed: sequence 2 is valid to 2027-01-03 and its lock has not changed.

When all three are done, tell the Mac session: "Chromebook steps 6, 7, 10 done", with the output of
`git -C ~/flagship log --oneline -5 origin/main`.

If a step fails: do not retry blindly. An endorsement cannot be un-signed (endorse a newer commit instead); an
artifact sequence is never reused (the script picks the next one). Copy the error to the Mac session.

   10-30 minutes). Export compliance should not be asked (the app declares no non-exempt encryption); if it is,

   ```

   ```
3. Task **B6** of `0.4-browser-tasks.md` with **build 11** wherever it says build 9 (version 1.3, texts per language,
   the three in-app purchases, the age rating check, the review notes). In "Version Release" choose **Manually
   release this version**, so nothing reaches users before the final tests pass.
4. **[OWNER CONFIRMS]** Add for Review / Submit (version 1.3 with build 10 and the three in-app purchases).

owner. Then:
