# Flagship 0.4: the web console tasks (brief for a Claude-in-browser session)

You are a browser assistant working for the owner of Flagship (a personal-cloud app; company IBIS LLC). This page is
your whole brief: do the console steps below in the owner's own logged-in browser. Read it to the end before you
start. Everything you need is on this page or in the files it links to in the public repository
`github.com/ibisllc/flagship` (read them through `https://raw.githubusercontent.com/ibisllc/flagship/<branch>/<path>`;
the owner tells you the branch, normally `main` once 0.4 has landed, or `release/0.4` before).

## Rules (read first)

1. **Secrets never go into the chat.** When a console shows you a key, token, signing secret or downloads a key
   file, do not copy it into your replies, notes or any web form other than the one that asks for it. Tell the owner
   "a secret is ready: <name>", leave it on screen (or in the Downloads folder), and give them the exact command from
   this page to store it. The owner runs that command in their own terminal, from the repository's `apps/com`
   folder, and pastes the value at the prompt. You never run commands.
2. **Stop and ask the owner** before any step marked **[OWNER CONFIRMS]**: anything that costs money, accepts
   legal terms or an agreement, makes a tax or legal declaration, submits something for review, or deletes
   something. Say what the step will do and wait for a clear yes in the chat.
3. **Do only what is listed.** Do not change other settings, delete other records, or create other keys. If a
   screen does not match the description (consoles change), describe what you see and ask.
4. **Never touch the review demo account or server `playstore-test-0725`** in any console.
5. **Personal data**: you will see names, addresses and bank details. Don't repeat them in the chat beyond what the
   owner needs to confirm a step.
6. **At the end**, reply with a checklist: each task done, skipped or blocked (and why), and the list of secrets
   that are waiting for the owner, by name only.

## A. Let's Encrypt: rate-limit increase for `fshp.app` (do first: it takes days)

Direct addresses (`<app>--<user>.fshp.app`) each need a certificate; Let's Encrypt allows 50 a week per registered
domain. Background and wording to reuse: `docs/runbooks/le-high-volume-application.md` (written for
`flagship.services`; the same reasoning applies to `fshp.app`) and `docs/direct-access-and-domains.md` §8.

1. Open Let's Encrypt's rate-limit adjustment request form (linked from letsencrypt.org/docs/rate-limits, "Requesting
   a rate limit adjustment").
2. Fill it for the registered domain **`fshp.app`**: hosting provider giving each user's own server a subdomain; the
   certificates are issued to the users' own servers through DNS-01 by one ACME account. The form asks for the ACME
   account URI: ask the owner for it (they read it with
   `npx wrangler d1 execute flagship-state --remote --command "SELECT account_url FROM issuance_acme_accounts"`).
   Expected volume: ask the owner (a starting figure is a few hundred new certificates a week).
3. **[OWNER CONFIRMS]** submit. Report the confirmation the form shows.

   "Sandbox & Production", key restriction "Team Scoped (All Topics)". Download the `.p8` once (it cannot be
   downloaded again). Secrets for the owner:
   ```sh
   npx wrangler secret put APNS_PRIVATE_KEY_PEM < ~/Downloads/AuthKey_<KEYID>.p8     # then delete the file
   ```

4. Identifiers → the App ID `com.flagshipserver.app`: confirm **Push Notifications** and **In-App Purchase** are on.
