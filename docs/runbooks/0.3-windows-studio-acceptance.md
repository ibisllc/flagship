# 0.3 Windows Studio acceptance: dropping "Experimental"

Owner, 2026-11-02: Windows Flagship Studio loses its "Experimental" tag in 0.3 if it passes the tests
below. This is that test round. It applies the owner's Preview rule (`docs/preview-criteria.md`, criteria
1 to 6) to Windows Studio, and it covers every item the 2026-10-18 and 2026-10-19 Windows runs left open
(`AGENTS.md` "Validating on Windows and Linux"; `device-results/FINAL-ROUND-windows-2026-10-19.md` on
`origin/device-results/windows-2026-10-17`).

Who runs it: the device-test agent on the owner's Windows PC (`device-test-agent.md`), with the owner for
the phone, the UAC prompt, the USB stick and the metal machine. The brief to start that agent is at the
end. The release manager (the Mac) sets up the preconditions and fixes anything that fails.

**Backend: the GYM.** 0.3 is not on production, and a 0.3 Studio cannot install against the 0.2
production (its recipes name an exact box commit that production has not published). Everything below
talks to `gym.flagshipserver.com`, `webapp.gym.flagshipserver.com`, `remote.gym.flagshipserver.com` and
`*.gym.flagship.services`, except W1b (upgrade from 0.2) and W23 (after publication).

## The decision rule

- **Verdict PASS** = every row marked **R** below passes on one Studio build of the `release/0.3` line,
  on Windows 11 x64, plus row W0b on Windows 10 22H2 x64. A row may be "n/a" only with the owner's
  written waiver in the report (for example no machine with legacy BIOS). Rows marked **I** are recorded but do not decide the verdict.
- Any R failure is a bug: the Mac fixes it with a regression test, a new CI build is made, and the
  failed row and every row that touches the changed code are run again on the new build.
- The report says `Verdict: PASS` or `Verdict: FAIL` on a line of its own. `scripts/release.sh` (step
  `studiowl`) drops the tag only if an origin `device-results/windows-<date>` branch has a
  `device-results/windows-0.3-acceptance-<date>.md` with `Verdict: PASS`. Without it Windows ships
  tagged "Experimental" again; that does not block the 0.3 release.
- W23 runs after the public build exists. If it fails, the tag goes back on (`windows: true`, then
  `node scripts/check-versions.mjs --write`, a new Studio build and a `.com` redeploy).
- Code signing is **not** part of the verdict, and the 0.3 build is unsigned (owner, 2026-11-02, below).
  SmartScreen and Smart App Control prompts are expected: rows record them and never fail on them.

## Supported Windows (owner decision, 2026-11-02)

- **Windows 11, any version Microsoft still services for its edition, x64.** As of 2026-11-02 that is
  25H2 (and newer) for Home and Pro, and 24H2 and newer for Enterprise and Education. Verify these dates
  on Microsoft's Windows 11 lifecycle page before quoting them; they are general knowledge, not checked
  here.
- **Windows 10 22H2, x64.** Supported, though it no longer gets security updates for most users (the
  consumer Extended Security Updates year ended on 2026-10-13). Studio tells Windows 10 apart by its
  build number (below 22000) and shows one calm line at the top of the window: "This version of Windows
  no longer gets security updates. Studio still works here and can host your server; updating to
  Windows 11 keeps this PC safer." (`WindowsSupport.cs`, all six languages). It never blocks anything.
- Nothing in Studio needs a Windows 11-only API (checked 2026-11-02): WPF on .NET 8 (Windows 10 1607
  and later), DPAPI for saved Wi-Fi, `SetThreadExecutionState`, `GlobalMemoryStatusEx`, the raw disk
  write (`CreateFile`/`DeviceIoControl`), the WPF taskbar progress (`TaskbarItemInfo`, Windows 7 and
  later), the tray icon, `wmic` / `Get-PhysicalDisk`, UAC elevation, and QEMU with the Windows
  Hypervisor Platform (WHPX exists since Windows 10 1803). `app.manifest` declares the Windows 10/11
  compatibility id.
- Arm64 Windows is not supported (the zip is x64; the appliance is amd64).

The test PC records `winver` (edition, version, build) in the report. A second Windows 11 install on a
different version or language (W20) is welcome but not required. Row W0b needs a Windows 10 22H2 PC.

## Code signing (owner decision, 2026-11-02: not for 0.3)

The Windows zip stays **unsigned** in 0.3 (`studio-release.yml`: "Not code-signed yet, so SmartScreen
will warn"). The prompts below are expected: every row that meets one records it (dialog title,
publisher line, the clicks needed, or that it was blocked) and the row is judged on what Studio does
once it runs. What that means for users:

- On a normal Windows 11 PC, SmartScreen shows "Windows protected your PC" with an unknown publisher;
  the user must click More info, then Run anyway. The bundled `tools\xorriso.exe` is unsigned too.
- On a PC with **Smart App Control** on (new Windows 11 installs start it in evaluation mode and may
  turn it on), an unsigned app with no reputation is **blocked with no Run anyway**. Studio would not
  start at all for those users. W1 records the PC's Smart App Control state and what happened.

Signing is not a prerequisite for dropping "Experimental": `preview-criteria.md` defines the tag by
function on real hardware, and the owner decided on 2026-11-02 not to sign 0.3. The `/studio` page
keeps saying the Windows build is unsigned. For a later release, the options and rough costs (check
current prices and eligibility before buying):

| Option | Cost (approx.) | Notes |
|---|---|---|
| Azure Trusted Signing (Microsoft's managed signing, Basic tier) | about US$10 a month | Cheapest; keys live in Microsoft's HSM; signs from GitHub Actions with a service principal. Identity validation for an organization needs a verifiable business history (IBIS LLC: check eligibility). |
| OV code-signing certificate from a CA (DigiCert, Sectigo, SSL.com...) | about US$200 to 500 a year | Since June 2023 the key must be on a hardware token or a cloud HSM, so CI signing needs the CA's cloud signing service (extra cost) or a self-hosted runner with the token. |
| EV code-signing certificate | about US$300 to 700 a year | Same hardware-key rule. Since 2024 EV no longer gives instant SmartScreen reputation, so it buys little over OV for us. |

Either way SmartScreen reputation builds with downloads, so a signed build may still warn for its first
weeks. Signing adds a `studio-release.yml` step (sign `Flagship Studio.exe` and `tools\xorriso.exe`,
then verify with `signtool verify /pa`), and the CI check that the exe reports the release version stays.
