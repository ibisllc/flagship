# Languages

Flagship is written in English and ships in the languages listed in `i18n/locales.json`. Every surface reads that
one file. A language is **`draft`** (translations are generated and kept in `i18n/`, but nothing ships or is served)
or **`ga`** (packaged, shown in the pickers, offered by Accept-Language). Turning one on is one line:

```
"status": "ga"        # i18n/locales.json, then: npm run i18n   (it lists anything still missing)
```

`npm run i18n` runs every check; `npm run i18n:status` shows coverage per surface and language.

## Where the text lives

| Surface | Source of truth | Native output | Tool |
|---|---|---|---|
| Websites (marketing, docs, FAQ, security, blog) | the English `apps/web/public/*.html` + `i18n/web/<lang>.json` | static pages under `apps/web/public/<lang>/` | `scripts/i18n-web.mjs` |
| Android app, Wear OS | `i18n/android`, `i18n/wear` | `res/values-<lang>/strings.xml` (+ `locales_config.xml`, per-app language) | `scripts/i18n-android.mjs` |
| iPhone/iPad app, widgets, Watch | `i18n/ios`, `ios-widgets`, `watch`, `watch-widgets`, `ios-infoplist` | `Localizable.xcstrings`, `InfoPlist.xcstrings` per bundle | `scripts/i18n-ios.mjs` |
| Studio for macOS | `i18n/studio-mac` | `Resources/<lang>.lproj/Localizable.strings` (Makefile copies them in) | `scripts/i18n-ios.mjs --mac` |
| Studio for Windows | `i18n/studio-windows` | `src/Strings.<culture>.resx` satellite assemblies | `scripts/i18n-windows.mjs` |
| Studio for Linux | `i18n/studio-linux` | gettext `po/<lang>.po` → `.mo` | `scripts/i18n-linux.mjs` |
| Server → phone | `packages/control-plane/src/pushBridge.ts` | APNs `loc-key` (the English sentence is the key) | `scripts/i18n-server.mjs` |

`i18n/glossary.json` fixes the product vocabulary (what is never translated, and the one word each language uses for
server / phone / device / backup …).

## Writing code that stays translatable

* **Never build a sentence from pieces** (`"Restored " + n + " app" + (n == 1 ? "" : "s")`). Use one string with
  arguments, or a plural resource (`<plurals>` on Android, a plural variation in the catalog).
* **Android:** inside a Composable use `stringResource(R.string.x)` / `fsString(R.string.x, a, b)`; elsewhere
  `FSStrings.get(R.string.x, a, b)` and `FSStrings.plural(R.plurals.x, n, n)`. Read the text when you need it; do not cache it in a field.
* **iOS:** `Text("literal")` and the other SwiftUI initialisers are keys already. Where you need a `String`, write
  `String(localized: "…")`. Interpolating a number groups its digits per locale; keep `String(n)` where a cross-platform test vector pins the digits.
* **Studios:** C# `Strings.T("key")` / `Strings.F("key", args)`, XAML `{local:Str key}`; Python `tr("…")`; Swift as iOS.
* **After editing English text:** re-run the surface's `wrap` / `extract` / `harvest` (see the script header), commit the changed JSON.
  A changed English sentence makes its old translation stale; `check` reports it and the app falls back to English for that string.
* **Dates, numbers, sizes:** use the platform formatter for the user's locale, not a hand-built pattern.

## Review

Translations are machine-written drafts. The reviewer's brief is `i18n/REVIEW.md`. Security and recovery wording gets
a native speaker before a language becomes `ga`.
