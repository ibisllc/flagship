# 0.3 translation review: notes for the native reviewers

Prepared during plan item F4b (2026-11-01). The release already plans a native review of every
language; this file lists what that review should look at first. Nothing here blocks the release.

## 1. One word for "box"

`i18n/glossary.json` fixes the word for "box" (the machine a server runs on; never the word for
"device"). The apps follow it. The website did not in three languages; it now uses the apps' word.

| Language | Glossary and apps (webapp, iOS) | Website before F4b | Website now | Still different |
|---|---|---|---|---|
| es | equipo | caja (26 strings) | equipo | none found |
| fr | boîtier | boîtier | unchanged | none found |
| de | Box | Box | unchanged | none found |
| pt-BR | caixa | caixa | unchanged | none found |
| ja | ボックス | 箱 (19 strings), ボックス (3) | ボックス | Studio Mac, Windows and Linux use 箱 ("箱がネットワークに届い…", 4 strings) |
| zh-Hans | 主机 | 盒子 (23 strings), 主机 (5) | 主机 | Studio Windows uses 盒子 (2 strings, e.g. "盒子可能没有连上网络") |

Counted over every English string containing "box" (website 26, webapp 49, iOS 12; Android's
English strings never say "box"). Please check:

- **es:** the move from "caja" to "equipo" changed gender in 26 site strings ("un equipo robado",
  "¿Está encendido el equipo?", "Vincúlalo", "volver a encenderlo"). Read help.html and the docs
  page for agreement errors. The landing line now reads "Conecta en casa un pequeño equipo":
  is that natural marketing Spanish, or should the glossary pick another word?
- **ja:** 箱 read more naturally in the landing copy ("小さな箱を自宅につなぎ"); the site now says
  ボックス like the apps. Decide which one the glossary keeps, then align the Studios.
- **zh-Hans:** 盒子 suits the landing copy ("一台小盒子"); the site now says 主机 like the apps.
  Same decision. The Pi answer avoids "迷你主机" for mini-PC (now 迷你电脑) so 主机 keeps one meaning.

## 2. Strings written in F4b without a native speaker

Written carefully by hand (not machine output), all six languages. Pages: `index.html`,
`faq.html`, `security.html`, `docs/index.html` (source: `i18n/web/<lang>.json`).

- Landing hero line: "3,000+ tests, all green" (was 1,489).
- Store buttons: "App Store" / "Google Play" labels (were "iOS soon" / "Android soon") and their
  titles "Flagship on the App Store" / "Flagship on Google Play".
- Raspberry Pi answers (landing and FAQ) and the FAQ hardware answer: x86-64 for the USB
  installer, arm64 only as a VM hosted by Studio on an Apple-silicon Mac. "Apple silicon" is
  rendered "Apple silicon" (es), "puce Apple" (fr), "Apple-Chip" (de), "Apple Silicon" (pt-BR),
  "Apple シリコン" (ja), "Apple 芯片" (zh-Hans): check against Apple's own localized wording.
- security.html, "What we promise": the boot-unlock line now explains opt-in Auto-unlock, revoking
  a stolen server, and the 7- or 30-day time limit.
- docs page, "Install & first boot": the stolen-box sentence now covers Auto-unlock.
- docs page, "Phone pairing": four new paragraphs (QR codes are https links; Remote; adding a
  device on an admin device; Studio). Menu paths reuse the apps' own translations ("Settings →
  Browser sessions", "Trusted devices", "Add a device", "Connect to an existing account"). The
  English page says "Add device" where the apps say "Add a device"; the translations follow the apps.
