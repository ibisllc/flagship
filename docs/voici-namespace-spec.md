## Owner clarifications (2026-11-02, binding)

1. **GRACE = 30 days.** A given-up username (account deleted; later, renamed) is *held* for 30 days: nobody
   can claim it, so caches and old links go stale before a new holder appears. Holding gives **no priority**
   to anyone, the previous owner included: there is no "rename back to a held name" (drop the doc's
   "Rename back" lifecycle row and test T16), so nobody can squat names by discarding them. After 30 days
   the name is released and anyone may claim it, first come first served.
2. **Renames:** 0.3 ships the registry with the held/redirect machinery and its tests; the rename action
   itself (paid name change) stays on `feat/custom-names` and uses the registry when it ships.
3. Account deletion today frees the name at once (`docs/account-deletion-and-name-reclaim.md` §1); with
   the registry it is held 30 days instead. Update that doc.

## The spec (verbatim text of the doc)

voi.ci namespace: implementation spec
 · 
This spec sets the naming conventions for voi.ci: what a username, custom link name or code may look like, how they're kept from colliding, and how voi.ci/<x> is resolved. Profile pages (voi.ci/<username>), custom link names and system-minted codes all claim their path through one registry, which replaces the current plain collision check.
Out of scope. Security and abuse protections (rate limits, link-destination checks, message spam, quotas) aren't decided here. Known risks and reviewer suggestions are listed at the end, under Security considerations, for information only. The grace period for given-up names isn't set here either: keep whatever value the code currently uses.
Basis. Harry decided the rules marked Decided on 2026-11-02, and they are final. Rules marked Adopted come from the external review; Harry didn't change them.

Resolution
Every request to voi.ci goes through one function. Lookups match on the exact name, not the safety key: voi.ci/pluckyavocet does not redirect to plucky-avocet. Released rows are ignored.

Lifecycle
Every status change is a single transaction. GRACE below means the grace period the code already uses; this spec doesn't change it.
Event
 | Change in names
 | Effect
 | 
Sign-up
 | Insert username, active
 | The profile URL exists; the page is unpublished until the owner publishes it.
 | 
Rename A → B
 | In one transaction: insert B active; set A to held, held_until = now() + GRACE
 | voi.ci/A redirects to voi.ci/B during the grace period. If B is taken, nothing changes.
 | 
Rename back to a held name
 | Same owner only: set that held row to active and hold the current name
 | Lets an owner undo a rename during the grace period.
 | 
Account deleted
 | All the account's username rows → held, held_until = now() + GRACE; its links and codes → retired
 | Held names return 404 (no account to redirect to).
 | 
Grace period ends
 | Scheduled job: held rows past held_until → released
 | The safety key stops blocking, so anyone may claim the name (D6). Keep the row for history.
 | 
Link name deleted
 | link → retired
 | Returns 410. The name stays blocked (D7).
 | 
Code deleted
 | code → retired
 | Returns 410. Never reissued (D7).
 | 
Reserved word added
 | Insert reserved, active
 | Fails if the word is already claimed; handle that case by hand.
 | 
A released username claimed by a new account is a brand-new row. Nothing from the old row (history, messages, page) carries over.
Reserved words
Reserved words are reserved rows in names, so the safety-key index blocks them and their look-alikes the same way it blocks any other name. They apply to both usernames and custom link names. Load them from a config file at deploy time, and extend them there, not in code.

Security considerations (not decided)
Nothing in this section has been decided by Harry. These are risks and suggestions from the external review, kept here for context. Don't implement any of them as part of this spec without his sign-off.
Risk
 | Suggestion
 | 
Released usernames reach the wrong person. After the grace period, old business cards and links that use a released name lead to the new owner, and visitors may send that owner messages meant for the previous one.
 | A longer grace period; release a name only if it has had no traffic for some time; show a "this name changed owner" notice on the page for a while.
 | 
Phishing through custom links. A name like voi.ci/payroll or voi.ci/verify redirecting to an outside site borrows the trust of a domain that also hosts personal pages.
 | Allow links only to the owner's own apps, or check destinations against a URL-reputation service and show an interstitial for new accounts. Add a report and takedown path. Reserve sensitive words (payroll, verify, bank, billing, government and brand names).
 | 
Squatting on link names. Retired link names are blocked forever, so one account can use up many names by creating and deleting links.
 | Require a verified account for custom names, set a per-account quota, and count retired names against it.
 | 
Code guessing. With 6 characters (604.7M possible codes) and 1M live codes, about 1 random guess in 600 hits a real link.
 | Rate-limit 404s per client. Never treat a code as a secret: anything private behind a code needs its own access check. Raise CODE_LENGTH if scanning becomes a problem.
 | 
Name scanning. Generated adjective-noun names come from a small, predictable space, so anyone can scan for which ones have pages.
 | Return the same 404 for an unpublished page as for an unknown name. Keep the claim refusal generic ("taken or too similar"), which the spec already does.
 | 
Message spam. Public pages with a "Send me a message" button are easy targets.
 | Rate limits per sender and per recipient, plus a bot check on the form.
 | 
The username exposes more than a page. If the username is also a login identifier or the host name of the person's personal cloud, every business card gives that away.
 | Keep login and host identifiers separate from the public name, or confirm they already are.
 | 
Look-alikes beyond 0/o and 1/l. Pairs such as rn/m and vv/w aren't caught by the safety key.
 | Warn on these when a name is claimed rather than refusing them.
 | 
URL decoding tricks. Decoding a path twice can turn %2561 into a and reach a different name.
 | Decode once, and return 404 for any path with characters outside a-z 0-9 - @ /.
 |

### Data model (Postgres sketch; adapt to D1)

```sql
CREATE TYPE name_kind   AS ENUM ('username', 'link', 'code', 'reserved');
CREATE TYPE name_status AS ENUM ('active', 'held', 'released', 'retired');

CREATE TABLE names (
  id               bigserial PRIMARY KEY,
  name             text        NOT NULL,   -- canonical form, as in the URL
  safety_key       text        NOT NULL,   -- see Validation
  kind             name_kind   NOT NULL,
  status           name_status NOT NULL DEFAULT 'active',
  owner_account_id bigint      NULL REFERENCES accounts(id),  -- NULL for reserved
  target           text        NULL,       -- links and codes: destination
  held_until       timestamptz NULL,       -- set when status = 'held'
  created_at       timestamptz NOT NULL DEFAULT now(),
  status_changed_at timestamptz NOT NULL DEFAULT now()
);

-- The one rule that makes every collision check a constraint:
CREATE UNIQUE INDEX names_safety_key_live ON names (safety_key)
  WHERE status <> 'released';


CREATE INDEX names_name ON names (name);
```

### Validation

```python
import re, secrets

NAME_RE = re.compile(r"^[a-z0-9][a-z0-9-]{1,61}[a-z0-9]$")   # 3..63 chars, no edge hyphen

def valid_name(name: str) -> bool:
    return bool(NAME_RE.match(name)) and "--" not in name

def safety_key(name: str) -> str:
    return name.lower().replace("-", "").translate(str.maketrans("01", "ol"))

CODE_FIRST = "0123456789"
CODE_REST  = "0123456789abcdefghijklmnopqrstuvwxyz"

def mint_code(length: int = 6) -> str:          # CODE_LENGTH setting, currently 6 (D3)
    return secrets.choice(CODE_FIRST) + "".join(secrets.choice(CODE_REST) for _ in range(length - 1))
```

### Resolution

```python
def resolve(raw_path):
    p = raw_path.lower().rstrip("/")          # D13
    if p != raw_path:
        return redirect(301, "/" + p)
    if p == "":
        return home()
    if p.startswith("-/"):
        return system_route(p)               # D11

    if p.startswith("@"):                    # D10: usernames only
        row = lookup(p[1:], kinds={"username"})
        if row is None:
            return not_found()
        return redirect(301, "/" + current_username(row))   # bare form is canonical

    row = lookup(p)                          # status in (active, held, retired)
    if row is None or row.kind == "reserved":
        return not_found()

    if row.kind in ("link", "code"):
        if row.status == "active":
            return redirect(302, row.target)
        return gone_page(410)                 # retired: "this link was removed"

    # row.kind == "username"
    if row.status == "held":                 # old name during the grace period (D6)
        if account_deleted(row.owner_account_id):
            return not_found()
        return redirect(301, "/" + current_username(row))
    if page_published(row.owner_account_id):
        return profile_page(row.owner_account_id)
    return not_found()
```
